# F-006 ピックとチームの作戦の予想

## 背景

作者は、各試合で各選手が何をピックしそうか、相手が何を BAN しそうか、チームがどんな作戦(序盤の動き方・勝ち筋)を取りそうかを予想して見たい(価値責任者の要望、2026-10-08)。LTK には独自のドラフト規則があり、NEXT は2体をプロテクト(うち1体は BAN 可)、CORE は同じカードの直前の NEXT 戦で使われたチャンピオンを使えず、MASTERS CUP はシリーズ内でフィアレスになる(`docs/research/format-history.md` 節4、`docs/research/meta-draft.md`)。

価値責任者は、NEXT のプロテクトの予想も含めたいと述べた(2026-10-09 の備忘)。誰の得意チャンピオンを軸にしてプロテクトするかは、重要なチーム戦略であり、勝率にも効く。各試合の勝率の予想と予想ピックに加えて、プロテクトも表示する。

価値責任者の決定(2026-10-09): プロテクト候補は、軸にする2人の選手から1体ずつ選ぶ。ただし、ピックプールが極端に狭い選手がいれば、その選手の2体を守る。作戦の予想は、先にあり得る作戦の項目と選択肢を決め(Teamfight Manager 2 の戦略の指示の項目のように、レーンへの介入をどこまでするか、集合するかレーンを優先するか)、どれが採られそうかを確率と理由で示す。AI 分析の文章は、その上に添える補足とする。

価値責任者の方向づけ(2026-10-09): プロテクト候補は、大会のロールでの使用数・勝率、F-009 のピックプールの得意チャンピオン、F-011 のメタの重要チャンピオン(段階A/B)から選ぶ。プロテクトの勝率への効果は F-005 基準14 が受け持つ(この機能は NEXT の予想ピックとプロテクト候補を出力する)。

### スクリムの BAN・ピック(2026-10-12 追記)

非公式のファンサイト LTKDB(F-004 の `/input-ltkdb` の取り込み元)は、スクリムの各試合の BAN とピックの順(「BP詳細」。BAN・ピックの別、順番、チーム、ピックのロールと選手、チャンピオン。BAN しなかった枠は「NOBAN」)を持つ(2026-10-12 時点で 28 試合 390 行)。2026-10-14 の時点では、名簿の階級チーム同士の 15 試合が BP詳細を持ち、全体の順(1〜20 手)と BAN と PICK がそろうのは 8 試合(MASTERS CC 対 LR の 2・3 試合目、CORE LR 対 DD の 2・3 試合目、NEXT IT 対 DD の 1〜4 試合目)、BAN と PICK はあるが順の無いのが 3 試合(CORE DD 対 IT)、PICK 10 行だけなのが 4 試合(MASTERS IT 対 CC の 2〜4 試合目と、勝者だけが分かる MASTERS CC 対 LR の 1 試合目)。BAN の枠には「NOBAN」が 8 行、チャンピオン名が空の行が 4 行(いずれも CORE DD 対 IT)ある。価値責任者の依頼(2026-10-12)で、これをプロテクト候補と BAN 候補の材料にし、試合の分析ページに出す(基準 12〜15)。スクリムは課題を洗い出す場でもあるため、BAN・ピックの記録は候補の並びを補う材料に留め、見込みの値(基準1)は変えない。

## 用語

- **評価の試合・ピックプール**: F-009 のとおり。選手ごとの、大会のロールで3試合以上使ったチャンピオンの一覧(試合数と、(勝ち数 + 2.5) ÷ (試合数 + 5) で縮小した勝率)。評価のファイル(ratings.json)の `poolDetail` にある。数値の championId は Data Dragon の `key` で名前へ引く
- **メタの重要度 g**: F-011 のメタの一覧(`data/meta/<パッチ>.json`)で、そのロールの段階A なら 1.0、段階B なら 0.5、どちらでもなければ 0
- **見込みの値**: 選手 × チャンピオンの値。v = `pick.wGames`(初期値 0.5)× (試合数 ÷ その選手のピックプールの最大の試合数)+ `pick.wWin`(初期値 0.3)× 縮小した勝率 + `pick.wMeta`(初期値 0.2)× g。評価設定は `src/predict/config.json`
- **プロテクトの値**: 選手 × チャンピオンの値。u = v × w_r × (1 + `protect.metaBonus`(初期値 0.5)× g)。w_r は F-010 のロールの重み(MID 0.24 / JG 0.21 / SUP 0.21 / TOP 0.17 / ADC 0.17)
- **軸にする選手**: プロテクト候補のチャンピオンのプロテクトの値を与えた選手
- **ピックプールが狭い選手**: 大会のロールで3試合以上使ったチャンピオン(F-009 のピックプール)が `protect.narrowPool`(初期値 2)体以下の選手。0 体の選手は含めない
- **スクリムの BAN・ピックの記録** `draft`: F-004 のスクリムの記録(`docs/research/grounds/scrims/`)の任意の欄。1 試合の BAN・ピックを順番に並べた配列で、各要素は `order`(1 から始まる整数か null。null は元の記録に順が無い試合で、1 試合の要素はすべて整数かすべて null のどちらか)・`team`(記録の 2 つの階級チームのどちらか)・`type`(`BAN` / `PICK`)・`champion`(チャンピオンの一覧の日本語名か null。null は BAN しなかった枠(LTKDB の「NOBAN」)と、BAN したチャンピオンの名前が元の記録に無い枠)・`role`(`PICK` のときの名簿のロール。`BAN` のときは null)を持つ。`BAN` の要素を持たない `draft`(元の記録が PICK だけの試合)も受け付ける
- **相手からの BAN 数** b(階級チーム, チャンピオン): 基準 12 で受け付けた、名簿の階級チーム同士のスクリムの記録で、相手チームがその階級チームの試合で BAN した回数。`champion` が null の要素と、リスナー参加と重複の記録(F-004 基準 5・7)は数えない
- **スクリムの試合数** n_s(階級チーム): その階級チームの、`BAN` の要素を 1 つ以上含む `draft` を持つ受け付けたスクリムの記録の数(2026-10-14 の改訂。PICK だけの記録は b を増やさないため数えない)
- **順のある試合数** n_o(階級チーム): その階級チームの、`order` が null でない `draft` を持つ受け付けたスクリムの記録の数(2026-10-14 追記)
- **作戦の項目**: 表「作戦の項目と選択肢」の6項目。各項目は決まった選択肢を持つ。項目と選択肢と重みは評価設定 `src/predict/strategy.json` に置く
- **作戦の選択肢の点**: 階級チーム × 選択肢の値。z = Σ_i 重み_i × 入力_i。入力は F-010 の戦い方の特性(−1.0〜+1.0)、F-009 の軸の表示の点数を (点 − 5.0) ÷ 5.0 にした値、F-011 の `mainstreamStyle`、プロテクト候補のロール。採られる確率は項目ごとに p = exp(z) ÷ Σ exp(z)

### 作戦の項目と選択肢

Teamfight Manager 2 の戦略の指示の考え方(試合前に、レーンへの圧・オブジェクト・集団戦・マップの支配の方針を選ぶ)を借りた。同じゲームの項目名は公開資料で確かめられなかったため、項目は LoL の用語で独自に決めた(AI の起案)。

| # | 項目 | 選択肢 |
| --- | --- | --- |
| S1 | レーンへの介入(JG・SUP がレーンへ寄る量) | 多い / 普通 / 少ない(ファーム重視) |
| S2 | 集合かレーン優先か | 早めに5人で集まる / 状況で集まる / レーンとサイドを保つ |
| S3 | オブジェクトの優先 | ドラゴン側(下) / ヴォイドグラブ・ヘラルド側(上) / 均等 |
| S4 | 序盤の攻め | 先手(インベード・早い小競り合い) / 標準 / 守ってスケールを待つ |
| S5 | 資源を寄せるレーン | TOP / MID / BOT |
| S6 | 集団戦の始め方 | 先に仕掛ける / 受けて返す / 孤立した相手を狙う |

### スクリムの BAN・ピック(2026-10-12 追記)

| # | 型 | 受入基準 |
| --- | --- | --- |
| 12 | 望ましくない事象 | スクリムの記録の `draft` が、null でない `order` の重複か 1 未満の値、null の `order` と null でない `order` の混在、2 つの階級チーム以外の `team`、`BAN`・`PICK` 以外の `type`、チャンピオンの一覧に無い `champion`、`PICK` で null の `champion`、各チーム 5 件でない `PICK`、`PICK` の `champion` と同じチーム・同じ `role` の選手の行の `champion`(null の行は照合しない)の不一致(選手の行を持たない記録では照合しない)のどれかを含む場合、システムはファイル名・要素の番号・反した欄を出力し、F-004 基準 4 のとおり失敗の終了コードを返さなければならない |
| 13 | ユビキタス | システムは階級チームとチャンピオンごとに、相手からの BAN 数 b とスクリムの試合数 n_s を、F-005 基準14 の入力と同じ置き場の予想の出力(`data/public/next-draft.json`)の階級チームごとの欄 `scrimDraft` に書かなければならない。`draft` を持つ記録が無い階級チームは `scrimDraft` を null とする |
| 14 | ユビキタス | NEXT の階級チームで n_s が 2 以上の場合、システムはプロテクトの値を u × (1 + `protect.banBonus`(初期値 0.3)× min(1, b ÷ n_s))として基準 4 のプロテクト候補を選び、基準 4b の理由に「スクリムで相手から b / n_s 試合 BAN された」を書かなければならない。n_s が 2 未満の階級チームでは u を変えてはならない |
| 15 | イベント駆動 | 試合の分析ページを開いたとき、システムは各チームの BAN 候補(基準5)の下に、そのチームのスクリムの BAN・ピックの集計(相手から BAN された回数の多いチャンピオン上位 5 体と回数、そのチームが BAN した回数の多いチャンピオン上位 5 体と回数、最初のピック(そのチームの `PICK` のうち `order` の最も小さいもの。`order` が null の記録は数えない)のチャンピオン別の回数、集計に使った試合数 n_s と n_o)を表示しなければならない。n_s が 0 のチームは BAN の 2 つの集計の代わりに「BAN の記録なし」、n_o が 0 のチームは最初のピックの代わりに「順の記録なし」と表示する |

各基準には、違反すると失敗するテストが1つ以上必要です。

## スコープ外

- 勝率の計算と、プロテクトの勝率への効果(F-005。この機能は基準9 で入力を渡すだけ)
- 試合中のドラフトのライブの追跡
- スクリムの BAN・ピックの記録で見込みの値(基準1)と BAN 候補の並び(基準5)を変えること(基準 15 は表示だけ)
- リスナー参加のスクリムの BAN・ピック(F-004 決定 D2)
- LTKDB の BAN・ピックの記録を `draft` へ書き出す変換そのもの(`/input-ltkdb` の変換の変更として扱う)
- AI 分析の文章を数値の計算に使うこと(基準7)
