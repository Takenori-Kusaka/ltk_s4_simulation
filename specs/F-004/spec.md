# F-004 試合結果の入力(本番・スクリム)

## 背景

作者は、大会(2026-10-15〜11-22)の本番の結果と、開幕前と大会中のスクリムの結果を入れて、予測と評価を試合日ごとに更新したい。企画書は「実際の試合結果の入力と、それによる予測の更新」をコア機能の候補に挙げている(`docs/project-brief.md`)。

結果を読む側は 3 つある。F-005 は本番の結果から補正 θ を当て直し(F-005 基準 4)、連敗の数 k で気持ちの補正を加え(基準 11)、試合の分析ページに予測と実際を並べる(基準 8)。F-009 は直近の試合の記録(`GameRecord`)から対面との差で軸の補正を作る(F-009 基準 6〜8)。F-014 の根拠のストーリーは個人の行に印を出せる。この機能は、結果を記録する形と置き場、検証、各機能へ渡す経路を決め、公開の画面に出す。

### 価値責任者の方向(2026-10-11)

- スクリムは「チャレンジ・調整・練習・確認」の場で、本番の試合結果に大きくは影響しない。ただし **地力の評価、ピックプールの評価、キーマンの発見**には有用
- リスナー参加のスクリムはデータとして扱わない
- スクリム中の文字起こしは話者分離が無いため、コール力の根拠としては本人を特定できる箇所に限り確度「低」
- 本番の結果(Regular Stage 以降)は F-005 の補正 θ と連敗 k(気持ちの補正)の入力になる

この仕様の数値(`scrimGameWeight` 2.0、F-005 の `weights.scrim` を 0 にする起案、キーマンの印の規則)は AI の起案であり、**価値責任者の確定を要する**。

### LTKDB の 14 分の CS(2026-10-12 追記)

非公式のファンサイト LTKDB(`/input-ltkdb` の取り込み元)は、スクリムの各選手の 14 分時点の CS(「14分CS」。計測した時刻は「計測秒」で、多くは 840 秒)を持つ(2026-10-12 時点で 310 行中 294 行)。結果画面には 14 分の値が無いため、これまでスクリムはレーン戦の軸に効かなかった。価値責任者の依頼(2026-10-12)で、この値をレーン戦の軸の材料にする(基準 25〜27)。

### LTKDB の成績で既存の軸の精度を上げる(2026-10-14 追記)

価値責任者の決定(2026-10-14。原文は判定記録 `docs/gates/g4-F-004-2026-10-14-rejudge2.md` に置く):

1. 材料の出どころの名前の軸(「実戦」の軸)は作らない。LTKDB の値は、測っている資質に当たる既存の軸(地力・レーン戦・集団戦・連携・安定感・ピックプール)の精度を上げる材料にする。既存の軸に当たらない資質に限って新しい資質を検討する。合わない値を参照しないことも、合わない軸へ当てはめることもしない
2. 勝敗だけが分かる試合(結果だけの記録)はチームの強さ(F-005 の θ・λ)にだけ入れ、個人の点数には入れない(基準 28〜30。PR #150 の改訂)
3. リスナー参加の試合は使わない(決定 D2 のまま)
4. 順位の表の規則(F-014)は変えない

この追記は、LTKDB の各欄を測る資質ごとに既存の軸へ対応づけ(下の「LTKDB の欄の行き先」)、14 分の CS をレーン戦の材料にする規則(基準 26・27 の改定、基準 39・40)と、本番の試合を個人の評価へ入れる規則(基準 41〜43。未確定事項 2 を閉じる)を足す。安定感の計算・レーン戦の確度・相手の強さの補正は F-009 の基準 41〜46。値はすべて AI の起案であり、**価値責任者の確定を要する**。

### 最初の事例(2026-10-10 のスクリム)

LR CORE SUP 千燈ゆうひの配信(https://www.youtube.com/watch?v=AZbkNH5Z5-I )の結果画面から、LR CORE 対 DD CORE のスクリム 3 試合(配信内の 4〜6 試合目。3 試合とも DD CORE の勝ち)を書き起こした(`data/scrim/2026-10-10-lr-core-vs-dd-core.json`。手法は `data/scrim/METHOD.md`)。各試合に勝敗・試合時間・10 人のチャンピオンと K/D/A・ゴールド・ダメージ、名簿との対応づけと確度がある。DD CORE の JG・MID・SUP のチャンピオンは顔出し枠で隠れて読めない試合があり、LR CORE ADC の対応づけは表示名が違うため「推定」である。この仕様の記録の形は、この JSON に合わせる。

## 用語

- **試合結果の記録**: 1 試合(1 ゲーム)の結果を 1 要素とする JSON。本番の記録とスクリムの記録の 2 種類
- **本番の記録**: 大会の公式の試合(Regular Stage の NEXT・CORE 各 24 試合、MASTERS CUP の各回の準決勝 2 試合・3 位決定戦・決勝の各ゲーム、Playoffs の各マッチの各ゲーム)の記録。置き場は `docs/research/grounds/results/`
- **スクリムの記録**: 大会の 2 つの階級チームが、大会の外で行った 5 対 5 の練習試合の記録。置き場は `docs/research/grounds/scrims/`
- **記録のファイル**: `<YYYY-MM-DD>-<識別子>.json`(識別子は小文字の英数字とハイフン。例 `2026-10-10-lr-core-vs-dd-core.json`)。配列で 1 試合 1 要素。同じ日・同じ組の試合を 1 ファイルにまとめる
- **階級チーム**: 記録の中では `<チーム> <階級>`(例 `DD CORE`)。階級チーム ID は `DD-CORE`(名簿 `src/data/roster.ts` の `team` と `tier`)
- **記録の出典** `source`: `url`(配信のアーカイブの URL、または公式の結果ページの URL)を必ず持つ。配信なら結果画面の時刻 `resultScreenSec`(秒)を持つ。出典の無い記録は受け付けない
- **対応づけの確度** `mappingConfidence`: 「確信」「推定」「未確認」のどれかで始まる文字列。括弧の中に理由を書いてよい(例 `推定(リザルト画面の表示名が違う。同じ席・同じチャンピオン)`)
- **リスナー参加のスクリム**: `listeners` が true の記録。対象外
- **対面**: 同じ試合の相手チームの同じロールの選手
- **チャンピオンの一覧**: F-003 の `data/public/champions.json`(Data Dragon ja_JP)に、チャンピオンごとの数値の key を `keys`(例 `"Aatrox": 266`)として足したもの。記録の `champion`(日本語名)を key に引く。F-009 のピックプールの `championId` と同じ値
- **スクリムの試合の記録(GameRecord)**: スクリムの選手 1 人の 1 試合分を、F-009 の「評価の試合」と同じ形 `GameRecord`(`src/rating/types.ts`)にしたもの。下の「指標の対応表」で作る
- **スクリムの重み `scrimGameWeight`**: F-009 の評価設定 `src/rating/config.json` の `engine.scrimGameWeight`。スクリムの試合の記録の新しさの重みに掛ける係数。初期値 2.0(ソロランク 1 試合の 2 倍。AI の起案、価値責任者の確定を要する)
- **連敗の数 k・補正 θ・気持ちの補正**: F-005 の用語のとおり
- **予測**: その試合について、試合日より前に計算した最新の勝率表(`data/public/winrates.json` の `computedAt` が試合日の 0 時(JST)より前のもの)の、その試合の両チームの勝率(`pA`・`pB`)
- **14 分の CS** `cs14`: 選手の行の、試合開始から `cs14Sec` 秒の時点の CS(ミニオンとモンスターの合計)。`cs14Sec` は記録(試合)ごとに 1 つ
- **キル関与**: (キル + アシスト) ÷ チームのキル。チームのキルが 0 なら 0
- **キーマンの印**: スクリムで「ダメージ最多」「キル関与最多」だった試合の数から付ける表示だけの印。点数には入れない
- **日程の順**: 同じ試合日の本番の試合の並び。Regular Stage は日程(`src/sim/schedule.ts` の `REGULAR_DAYS`)のカードの順に、各カードは NEXT → CORE。MASTERS CUP は semi1 → semi2 → third → final で、final は G1 → G2 → G3。Playoffs は upperFinal → lowerSemi(2026-11-21)、lowerFinal → grandFinal(2026-11-22)で、各マッチは G1 → G4
- **試合 ID** `matchId`: Regular Stage は `RS-<日>-<ブルー>-<レッド>-<階級>`(例 `RS-1-CC-DD-NEXT`。F-006 と同じ形)、MASTERS CUP は `MC<回>-<試合>-G<n>`(試合は `semi1`・`semi2`・`third`・`final`)、Playoffs は `PO-<マッチ>-G<n>`(マッチは `upperFinal`・`lowerSemi`・`lowerFinal`・`grandFinal`)、スクリムは `SC-<YYYYMMDD>-<階級チーム ID>-<階級チーム ID>-G<n>`(2 つの ID は辞書順、n は同じ日・同じ組の記録の通し番号)

### 指標の対応表(スクリムの記録 → F-009 の指標のキー)

| 記録の欄 | F-009 の指標のキー | 使う軸 |
| --- | --- | --- |
| `damage` | `totalDamageDealtToChampions` | 地力(対面との比の対数)、集団戦の材料 |
| `goldPerMin`(無ければ `gold` ÷ 試合時間(分)) | `goldPerMinute` | 地力 |
| `deaths` | `deaths` | 安定感 |
| `kills`・`assists` | `kills`・`assists` | 記録として持つ |
| (`kills` + `assists`) ÷ チームの `kills` | `killParticipation` | 連携 |
| `damage` ÷ チームの 5 人の `damage` の合計 | `teamDamagePercentage` | 集団戦(MID・ADC) |
| `gold` | `goldEarned` | 記録として持つ |
| `cs`(あれば) | `totalMinionsKilled` | 記録として持つ |
| `level`(あれば) | `champLevel` | 記録として持つ |
| 勝敗(`winner` がその選手のチームか) | `win`(1 / 0) | ピックプールの勝率 |
| `champion`(日本語名 → チャンピオンの一覧の key) | `championId` | ピックプール |
| `cs14`(TOP・JG・MID・ADC で、自分と対面の両方の行に `cs14` があるとき。2026-10-14 改定) | `csAt14`(自分は自分の `cs14`、対面は対面の `cs14`。F-009 の軸の定義で差 `diff` として使う) | レーン戦(基準 26・39) |

(2026-10-14 追記)この表は本番の記録(基準 41)にも同じに当てる。

対応表に無い指標(`soloKills`、`laningPhaseGoldExpAdvantage`、`maxLevelLeadLaneOpponent`、`maxCsAdvantageOnLaneOpponent`、`enemyChampionImmobilizations`、`pickKillWithAlly`、`damageTakenOnTeamPercentage`、視界の指標)は持たない。F-009 基準 8 の規則で、その指標はその試合で除外され、軸に使える指標が 1 つも無い試合はその軸で除外される。レーン戦の軸は、TOP・JG・MID・ADC で `cs14` のある試合だけに効く(14 分の CS の差の 1 指標。SUP は効かない)。標準化は名簿の階級チーム同士の試合の差の分布で行う(基準 39。2026-10-14 改定。ソロランクの最大 CS 差は試合中の最大の差で、14 分の時点の差とは別の量のため)。

### LTKDB の欄の行き先(2026-10-14 追記)

LTKDB(`/input-ltkdb` の取り込み元)の各欄を、測る資質ごとに既存の軸へ対応づける。使わない欄は、どの資質も測らないか、他の欄と同じものを測るかを理由に書く。

| シート・欄 | 測る資質 | 行き先 |
| --- | --- | --- |
| リザルト詳細: ダメージ | 対面より多く与える力 / チームの中でダメージを担う割合 | 地力(対面との比の対数)/ 集団戦(MID・ADC のチームダメージ割合の差) |
| リザルト詳細: ゴールド(と試合時間) | 資源を稼ぐ力 | 地力(分あたりゴールドの差) |
| リザルト詳細: K・A(とチームのキル) | 味方の戦いに加わる力 | 連携(キル関与の差) |
| リザルト詳細: D | 落ちない力 | 安定感(デスの差。F-009 基準 41 のとおり、出来のばらつきには使わない) |
| リザルト詳細: 14分CS(と計測秒) | 序盤のレーンとジャングルで資源を取る力 | レーン戦(TOP・MID・ADC は対面との CS の差、JG はジャングルのモンスターが大半を占める CS の差。基準 26・39) |
| リザルト詳細: チャンピオン名・勝敗 | 使えるチャンピオンの幅と、そのチャンピオンでの勝ち | ピックプール(基準 16) |
| 対戦結果まとめ: 勝利チーム | チームの強さ | F-005 の θ・λ(基準 20。結果だけの記録は PR #150 の基準 29)。個人の点数には入れない(2026-10-14 の決定 2) |
| 対戦結果まとめ: 試合時間 | — | 分あたりゴールドの分母、評価の試合の条件(10 分以上) |
| リザルト詳細: プレイヤー名・サモナーネーム・チーム名・ロール・サイド | — | 名簿・日程との対応づけ(基準 2・3) |
| BP詳細 | 相手から警戒される度合い | F-006(BAN・ピック。この機能のスコープ外) |

| 使わない欄 | 理由 |
| --- | --- |
| KDA(K・D・A をまとめた値) | 中身をキル関与(連携)とデス(安定感)に分けて既に使っている。まとめた値を足すと同じ K・D・A を 2 回数える |
| K 単体・A 単体 | キル関与(連携)と同じものを測る。単体の数は試合の長さとチームのキルの数に引きずられる |
| レベル | 試合時間・キル・ゴールドと同じもの(経験値の稼ぎ)を測る。最終の値で、試合の長さに依る |
| 14分CS の SUP の行 | SUP は CS を取らない役割で、CS の差はどの資質も測らない |
| チーム KDA・チームゴールド・最大ダメージ | 5 人の行の和と最大で、選手の行と同じものを測る(取り込みの検算にだけ使う) |
| 14分CS優勢(自由記述) | 14分CS の値から出せる。同じものを測る |
| MVP・ゴールド@15・15分ゴールド優勢・CS・CS/分・15分CS | 2026-10-14 の時点で 43 試合すべてで空。値が入ったら、測る資質を決めてこの表を改める |

LTKDB の欄で測れない資質(既存の軸に当てる欄が無いもの。新しい軸は足さない):

| 資質 | 測れない理由 |
| --- | --- |
| スノーボール力(序盤の有利を広げる力) | 測るには 15 分のゴールドの差が要るが、LTKDB の「ゴールド@15」「15分ゴールド優勢」は 43 試合すべてで空 |
| TOP・JG・SUP の集団戦(前に立って受ける・止める働き) | 被ダメージの割合と行動妨害の欄が無い |
| JG の序盤の関与・SUP のレーン戦 | 序盤のキル関与と視界の欄が無い(JG は 14 分の CS だけがレーン戦に効く) |
| ソロキル(地力の一部) | ソロキルの欄が無い |
| 視界・オブジェクト(チームの指標) | 欄が無い |

## 受入基準

### 入力と検証

| # | 型 | 受入基準 |
| --- | --- | --- |
