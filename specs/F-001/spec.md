# F-001 大会ルールエンジンと優勝確率のシミュレーション

## 背景

LTK Season: Finale の得点規則は、同日の両階級勝利ボーナス、MASTERS CUP の順位点、Playoffs の特殊 BO4(GAME 3 が 2pt)を含む独自の規則で、試合ごとの勝率から優勝確率を暗算できない。作者は、試合ごとの勝率を入力として、大会形式どおりに残りの試合を何度も模擬し、各チームのシード確率・優勝確率を見たい。

この機能は計算だけを担う。勝率の推定(選手データ・レーティング)と画面は別の機能で扱う。開幕(10/15)前日までに動くことが企画書の中止条件1に当たる。

大会形式の出典は `docs/research/format-history.md`(節2・3・7)。

## 受入基準

用語: 「カード」は同じ日の同じ2チームの対戦。「勝率表」は階級(NEXT・CORE・MASTERS)ごと・チームの組ごとの、片方が1試合に勝つ確率。

| # | 型 | 受入基準 |
| --- | --- | --- |
| 1 | ユビキタス | システムは Regular Stage の6日・各日2カードの対戦とブルー/レッドを、`docs/research/format-history.md` 節2.1 の表と同じ値で保持しなければならない(QC-04) |
| 2 | イベント駆動 | Regular Stage の1カードの NEXT 戦と CORE 戦の勝者が与えられたとき、システムは各チームへ1勝1pt を与え、同じチームが両方に勝った場合はそのチームへさらに1pt を与えなければならない(QC-04) |
| 3 | イベント駆動 | MASTERS CUP の1回分(準決勝2試合、3位決定戦、決勝)の勝者が与えられたとき、システムは1位3pt・2位2pt・3位1pt・4位0pt を与えなければならない。準決勝の組み合わせは節2.2 の表の固定値を使わなければならない(QC-04) |
| 4 | イベント駆動 | Regular Stage と MASTERS CUP の全試合の結果が揃ったとき、システムは両者の合計 pt の降順でシード1〜4位を決めなければならない |
| 5 | 望ましくない事象 | 合計 pt が同点のチームがある場合、システムは設定で選んだ同点処理(既定: Regular Stage の pt が多い方を上位とし、それも同点なら乱数で決める)で順位を決め、どの同点処理を使ったかを結果に含めなければならない |
| 6 | イベント駆動 | Playoffs の1マッチを模擬するとき、システムは GAME 1・GAME 2 の勝者へ各1pt、GAME 3 の勝者へ2pt を与え、2-2 の場合は GAME 3 に出ていない階級で GAME 4 を行い、その勝者をマッチの勝者としなければならない |
| 7 | イベント駆動 | Playoffs の1マッチを模擬するとき、システムは上位シードのチームが各 GAME の出場階級を、設定で選んだ方針(既定: 上位シードの勝率が最も高い階級を GAME 3 に置く)で決めなければならない |
| 8 | ユビキタス | システムは Playoffs を 1位 vs 2位(Upper Final)、3位 vs 4位(Lower Semifinal)、Upper Final の敗者 vs Lower Semifinal の勝者(Lower Final)、Upper Final の勝者 vs Lower Final の勝者(Grand Final、アドバンテージなし)の順で模擬しなければならない |
| 9 | イベント駆動 | 勝率表、確定済みの試合結果、試行回数、乱数の種が与えられたとき、システムは確定済みの試合を結果どおりに扱い、未確定の試合だけを勝率表に従って模擬し、各チームの「シード1〜4位の確率」と「優勝確率」を返さなければならない |
| 10 | ユビキタス | システムは同じ勝率表・確定済みの結果・試行回数・乱数の種に対して、同じ確率を返さなければならない(QC-02) |
| 11 | ユビキタス | システムが返す優勝確率の4チームの合計は 1 から 1e-9 以上ずれてはならない。各チームのシード1〜4位の確率の合計も同じ条件を満たさなければならない(QC-03) |
| 12 | 望ましくない事象 | 勝率表に 0 未満・1 超・数値でない値がある場合、または対戦に必要な組の勝率が無い場合、システムは模擬を始めずに、該当する階級とチームの組を含むエラーを返さなければならない |
| 13 | 望ましくない事象 | 確定済みの試合結果が大会の日程に無い対戦を指す場合、システムは模擬を始めずに、その結果を特定できる内容を含むエラーを返さなければならない |
| 14 | ユビキタス | システムの計算部分はブラウザと Node.js の両方で、DOM や Node 固有の API に依存せずに動かなければならない(ADR-0001) |

各基準には、違反すると失敗するテストが1つ以上必要です。

## スコープ外

- 勝率表の推定(選手データ・レーティング・Riot API)。F-003 以降で扱う
- 画面への表示。F-004 で扱う
- 試合結果の入力の画面と保存。F-002 で扱う
- ドラフト(プロテクト・BAN・CORE の使用禁止・フィアレス)とピック予想
- サイド(ブルー/レッド)が勝率に与える影響。保持はする(基準1)が、計算には使わない
- MASTERS CUP のサイド選択権の決定
- 代打・練習制限の影響

## 前提

| # | 前提 | 崩れたときの影響 |
| --- | --- | --- |
| 1 | 大会の日程と得点規則が `docs/research/format-history.md` 節2・3 のとおり(2026-10-08 時点の公式発表) | 運営が変更した場合、基準1〜8 の値を直す |
| 2 | 試合の勝敗は、同じ階級の同じ組では勝率表の確率に従う独立な事象として扱う | 調子の波や連敗の影響を表せない。必要なら別機能でモデルを変える |
| 3 | MASTERS CUP の決勝(BO3)は、1試合の勝率から2勝先取の確率として模擬する | BO3 の内部(フィアレス等)の影響は表さない |

| 項目 | 要求 |

| 応答時間 | 試行 10,000 回の模擬が、作者の PC の Node.js で 2 秒以内に終わる |

| 監査ログ | 不要 |

## 未確定事項

- [NEEDS CLARIFICATION] 同点処理の既定値(基準5)。公式規定は未確認。S3 の実例(CC と LR が 11pt で LR が上位)は「Regular Stage の pt 優先」と「Regular Stage の直接対決」の両方と矛盾しない。既定を「Regular Stage の pt 優先」としてよいか
- [NEEDS CLARIFICATION] Playoffs の階級の割り当て方針の既定値(基準7)。S3 では上位シードが自軍の強い階級を GAME 3 に置いた例が多い。他の方針(相手の弱い階級を先に当てる等)を選択肢として持つか
- [NEEDS CLARIFICATION] 試行回数の既定値(10,000 回でよいか)
