# F-002 選手・チーム・階級のキャラクターシート(多軸レーダー)

## 背景

作者は大会当日まで、60選手と4チームをキャラクターシートのように眺めて本番を妄想したい(価値責任者の要望、2026-10-08)。各選手の立ち絵と、LoL の重要能力5軸を10点満点(小数第一位)で示す五角形のレーダーチャートを見たい。チーム全体と階級(NEXT・CORE・MASTERS)単位でも同じ形のレーダーを見たい。

この機能は、選手ごとの指標の入力ファイルから評価の軸の点数(計算は F-009)を求め、SPA の画面に表示する。指標の収集(Riot API)は F-003 で扱い、この機能は入力ファイルの形式を定める。

## 用語

- **評価の軸**: F-009(評価モデル)の評価設定が定める軸(2026-10-08 時点で 8 軸)。当初の5軸(個人技量 / レーン戦 / チームファイト / コール・大会経験 / プールとメタ適合)は ADR-0004 で置き換えた
- **指標ファイル**: 選手ごとの数値指標(ランク、KDA、チャンピオン別の使用数と勝率、直近の試合の一覧)と手入力の評価を持つ JSON。形式は `src/data/` の型定義を正とする
- **採点規則**: 各軸の点数を指標から計算する重みと換算の表。`src/data/scoring.json` に置き、コードを変えずに調整できる

## 受入基準

| # | 型 | 受入基準 |
| --- | --- | --- |
| 1 | イベント駆動 | 選手のページを開いたとき、システムは選手名・チーム・階級・ロール・評価の軸のレーダーチャート(軸の数の多角形)と、各軸の点数を 0.0〜10.0 の範囲で小数第一位まで表示しなければならない |
| 2 | ユビキタス | システムは各軸の点数を、F-009 の評価モデル(指標ファイル・根拠・評価設定)から計算し、同じ入力に対して同じ点数を返さなければならない |
| 3 | イベント駆動 | 選手のページで軸の点数を選んだとき、システムはその点数の計算に使った指標の値と、採点規則の重み、指標の出典と取得日を表示しなければならない |
| 4 | 望ましくない事象 | 選手の指標ファイルにある軸の計算に必要な指標が無い場合、システムはその軸を「データなし」と表示し、レーダーではその軸を 0 ではなく欠損として区別して描かなければならない |
| 5 | イベント駆動 | チームのページを開いたとき、システムはチーム全体・NEXT・CORE・MASTERS の4つの評価の軸のレーダーを表示しなければならない |
| 6 | ユビキタス | システムは階級のレーダーの各軸を、同じ階級の4チームの中での相対評価(当該チームの5選手の平均点を、4チームの平均と標準偏差で標準化し、5.0 + 2.0 × 標準化した値を 0.0〜10.0 に切り詰めた値)で計算しなければならない |
| 7 | ユビキタス | システムはチーム全体のレーダーの各軸を、そのチームの NEXT・CORE・MASTERS の3階級の相対評価の点数の平均で計算しなければならない |
| 8 | 状態駆動 | 公開版(GitHub Pages)として動いている間、システムは選手の立ち絵の代わりに、ロールのアイコンと選手名の頭文字を描いた代替表示を出さなければならず、リポジトリと配信物に立ち絵の画像を含めてはならない |
| 9 | 任意機能 | 利用者が自分のブラウザで選手の画像ファイルを選んで登録する機能を備える場合、システムはその画像をそのブラウザの中だけに保存し、その選手のページで代替表示の代わりに表示しなければならず、画像をサーバーやリポジトリへ送ってはならない |
| 10 | ユビキタス | システムの画面は幅 360px のスマホと幅 1280px の PC の両方で、横スクロールなしにレーダーチャートと評価の軸の点数を表示しなければならない |
| 11 | 望ましくない事象 | 指標ファイルが型定義に合わない場合、システムは画面を描く前に、該当する選手と項目名を含むエラーを表示しなければならない |
| 12 | イベント駆動 | 選手のページで直近の戦績を開いたとき、システムは指標ファイルにある直近の試合を新しい順に、日付・キューの種類(ランク / スクリム / LTK 本番)・チャンピオン・勝敗・KDA・CS を1行ずつ表示しなければならない |
| 13 | イベント駆動 | 選手のページで生データを開いたとき、システムはその選手の指標ファイルの全項目を、項目名・値・出典・取得日の表で表示しなければならない |

各基準には、違反すると失敗するテストが1つ以上必要です。

## スコープ外

- 指標の収集(Riot API、手入力の調査の取り込み)。F-003 で扱う
- 評価の軸の点数から試合の勝率を推定すること。F-001 の勝率表の作成は別の機能で扱う
- 立ち絵の画像の収集・同梱・配信
- スクリム・本番の結果の入力の手段(F-004 で扱う)。この機能は、指標ファイルに入った結果を表示するだけ
- 選手どうしの比較画面(2人を重ねたレーダー)
- 過去の点数の推移のグラフ

## 前提

| # | 前提 | 崩れたときの影響 |
| --- | --- | --- |
| 1 | 60選手の名前・チーム・階級・ロールは公式発表(2026-10-07)のとおり | 代打や変更があれば選手データを直す |
| 2 | 指標の一部(コール・大会経験)は Riot API で取れず、手入力の評価(調査 `docs/research/` からの転記)に依る | 手入力が無い選手は基準4 の「データなし」になる |
| 3 | 階級の相対評価は4チームの比較であり、階級の間の絶対的な強さの差は表さない | 階級をまたいだ比較はできない(価値責任者の選択) |
