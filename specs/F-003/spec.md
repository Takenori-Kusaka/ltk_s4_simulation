# F-003 選手・メタのデータの収集(静的・現在)

## 背景

根拠のあるシミュレーションには、60選手の過去と現在のデータと、LoL のメタのデータが要る(価値責任者の要望、2026-10-08)。ADR-0003 の分類のうち「静的(過去)」と「現在」をこの機能が集め、ADR-0003 の形(値・出典・取得日・確度・書いた主体)で保存する。「未来」(スクリム・本番の結果)は F-004 で扱う。

現在の数値は Riot 公式 API で取る(ADR-0002)。op.gg を含む戦績サイトの画面は自動取得しない。過去の数値と定性の評価は、調査(人または AI)のスナップショットとして出典つきで保存する。

## 受入基準

| # | 型 | 受入基準 |
| --- | --- | --- |
| 1 | イベント駆動 | 収集を実行したとき、システムは Riot ID が登録された選手ごとに、現在のランク(ソロ・フレックス)と、前回の収集より後のランクの試合の詳細を Riot API から取り、取得日時とともに保存しなければならない |
| 2 | ユビキタス | システムは選手ごと・チャンピオンごとに、試合数・勝率・KDA・分あたり CS・分あたり視界スコア・チーム内のダメージ割合・キル関与率を、保存した試合の詳細から集計しなければならない |
| 3 | 望ましくない事象 | Riot API が HTTP 429 を返した場合、システムは応答の Retry-After の秒数だけ待って同じ要求をやり直し、収集を中断してはならない |
| 4 | 望ましくない事象 | 選手の Riot ID が未登録、または Riot API がその選手について HTTP 404 を返した場合、システムはその選手を「未取得」と記録し、ほかの選手の収集を続けなければならない |
| 5 | ユビキタス | システムは API キーを、保存するファイル・ログ・画面の配信物に書いてはならない |
| 6 | ユビキタス | システムは公開する配信物に、Riot API の生の応答ではなく、基準2 の集計値だけを含めなければならない |
| 7 | イベント駆動 | 静的なデータ(過去の LTK の戦績とピック、最高ランク、得意ピック、調査時点の戦績サイトの数値)のスナップショットのファイルを読み込んだとき、システムは出典・取得日・確度・書いた主体のどれかが欠けた値を拒否し、該当する選手と項目名を出力しなければならない |
| 8 | イベント駆動 | 定性の評価(IGL 力・コール力・性格・メンバー相性・コーチ・対面との相性・成長ポテンシャル)のファイルを読み込んだとき、システムは 0〜10 の点数と根拠の文章の両方を持つ評価だけを受け付け、根拠の文章の無い評価を拒否しなければならない |
| 9 | イベント駆動 | メタのデータ(パッチの強化・弱体の一覧、Worlds の使用率と BAN 率、ロールごとの Tier、ビルドとマクロの流行)のスナップショットを読み込んだとき、システムはパッチ番号と取得日をデータに付けて保存しなければならない |
| 10 | ユビキタス | システムはチャンピオンの一覧と名前を Riot の Data Dragon から取り、その版を保存しなければならない |
| 11 | イベント駆動 | AI 分析(Gemini CLI)に定性の評価の下書きを作らせるとき、システムは入力に調査資料の該当部分と出典を渡し、出力の評価を書いた主体「AI(モデル名)」として保存しなければならない |

各基準には、違反すると失敗するテストが1つ以上必要です。

## スコープ外

- op.gg を含む戦績サイトの画面の自動取得
- スクリムと本番の結果の入力(F-004)
- 試合のタイムライン(15分時点のゴールド差)の取得。試合ごとの追加の要求が回数制限を圧迫するため、初版では取らない
- 日次の自動実行の仕組み(F-007)。この機能は手動の実行で動く
- 採点・勝率の計算(F-002・F-005)

## 前提

| # | 前提 | 崩れたときの影響 |
| --- | --- | --- |
| 1 | 60選手の Riot ID(ゲーム名#タグ)を人か調査で特定できる | 特定できない選手は基準4 の「未取得」になる |
| 2 | 個人用 API キーの回数制限(20回/秒・100回/2分)で、日次の差分の収集が1時間以内に終わる | 収集の対象の試合数を減らす |
| 3 | Riot の Developer API Policy が、集計値の公開を認める | 公開版から数値を外す |

## 非機能の要求

| 項目 | 要求 |
| --- | --- |
| 応答時間 | 差分の収集が 60 分以内に終わる |
| 同時実行 | 1つの収集だけが動く(二重起動しない) |
| 監査ログ | 収集の開始・終了・選手ごとの件数・エラーをファイルに残す |

## 確定した事項(2026-10-08 決定)

- **集計対象の試合の範囲**: 初回収集は直近30試合(ソロ・フレックスのランクマッチ)、日次は前回収集日以降の差分試合を対象とする。個人用 API キーの回数制限(100回/2分)と所要時間(1時間以内)に収める
- **60選手の Riot ID の特定方法**: 一次情報として `docs/research/` の op.gg URL から URL デコードしてゲーム名#タグを抽出し、未確認・変更のある選手は技術判断者・価値責任者(人)が確認して手入力で補正・確定する(特定不能時は受入基準4で「未取得」としてフォールバック)
- **定性の評価の初版を誰が作るか**: `docs/research/` の調査資料に基づき Gemini CLI(AI)が「AI(Gemini)」名義で根拠文章つきの点数(0〜10)を下書きし、技術判断者・価値責任者 takenori-kusaka がレビューして確認・確定する(ADR-0003 決定3・受入基準11に準拠)
