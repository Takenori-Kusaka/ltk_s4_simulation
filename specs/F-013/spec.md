# F-013 勝率とシミュレーションの結果のページ

## 背景

価値責任者は、2026-10-10 のうちに、勝率の予想とシミュレーションの結果を GitHub Pages で確認できる状態にすることを求めた(2026-10-10)。F-001 のシミュレーション(`src/sim/`)は勝率表を入力に受け取る計算の部品で、画面を持たない(F-001 の仕様は画面を別の機能に委ねている)。F-005 は試合ごとの勝率表を作る(Task-1 で事前の勝率、`data/public/winrates.json`)。F-005 の Task-5 は試合ごとの分析ページで、大会全体の結果(順位の確率・優勝確率)を一望する画面はどの機能にも無い。

この機能は、F-005 の勝率表を読み、階級ごとの事前の勝率の表と、F-001 のシミュレーションの結果(順位の確率・優勝確率・期待の勝ち点)を1つのページに出す。計算は追加しない(勝率は F-005、シミュレーションは F-001 の関数をそのまま呼ぶ)。

## 用語

- **勝率表のファイル**: `data/public/winrates.json`(F-005 Task-1 の出力。`kind: "winrates"`、階級ごとの β、階級チームごとの S と理由、試合ごとの事前の勝率、F-001 の形式の `winTable`・`stageWinTables`)
- **事前の勝率**: F-005 基準5 の用語のとおり(β × (S_A − S_B) とステージ補正だけの勝率)
- **シミュレーションの結果**: F-001 の `simulate` の出力(シード1〜4位の確率、優勝確率、Regular Stage の期待勝ち点、MASTERS CUP の期待ポイント、使われた同点処理の回数)
- **固定の種**: 20261015。試行の数は 10,000(F-001 の既定)

## 受入基準

| # | 型 | 受入基準 |
| --- | --- | --- |
| 1 | イベント駆動 | `#/sim` を開いたとき、システムは階級ごと(NEXT・CORE・MASTERS)に、4チームの戦力 S(小数第二位まで)と β(小数第三位まで)、6組の事前の勝率(0.1% 単位。両チームの値)を表で表示しなければならない |
| 2 | イベント駆動 | `#/sim` を開いたとき、システムは勝率表のファイルの `winTable`・`stageWinTables` と固定の種・試行の数 10,000 で F-001 の `simulate` を1回だけ実行し、チームごとにシード1〜4位の確率(0.1% 単位)、優勝確率(0.1% 単位)、Regular Stage の期待勝ち点(小数第一位まで)、MASTERS CUP の期待ポイント(小数第一位まで)を表示しなければならない |
| 3 | ユビキタス | システムはシミュレーションの結果の表に、使った種・試行の数・勝率表のファイルの計算日時を表示しなければならない |
| 4 | 望ましくない事象 | 勝率表のファイルが無い、または `kind` が `winrates` でない場合、システムは `#/sim` に「勝率のデータがありません」と、集計のコマンド(`node src/collect/aggregate-cli.ts`)の名前を表示し、`simulate` を実行してはならない |
| 5 | 状態駆動 | 勝率表のファイルに戦力 S を計算できない階級チームがある間、システムはその階級チームが関わる組の行に「データ不足」と、ファイルにある理由を表示しなければならない |
| 6 | 状態駆動 | 結果の入力(F-004)が無い間、システムはページに「結果の反映: なし(開幕前の予想)」と表示しなければならない |
| 7 | イベント駆動 | ホームを開いたとき、システムは `#/sim` へのリンクを表示しなければならない |
| 8 | ユビキタス | システムの `#/sim` は幅 360px のスマホと幅 1280px の PC の両方で、横スクロールなしに表を表示しなければならない(表は横に送れる枠の中に置く) |
| 9 | ユビキタス | システムは `#/sim` の表示の値(勝率・確率・期待値)を、勝率表のファイルと F-001 の出力から丸めて作り、別の計算で作ってはならない |

各基準には、違反すると失敗するテストが1つ以上必要です(画面の論理は純粋な関数に分け、単体で検証する)。

## スコープ外

- 試合ごとの分析ページ(事前と更新後の勝率、上位3つの要因、β、区間、仕上がりと気持ちの内訳。F-005 Task-5)
- 結果の入力と、結果を反映した勝率の更新(F-004・F-005 Task-2)
- 80% の区間の表示(F-005 基準7b)
- 勝率表の計算そのもの(F-005)
- Playoffs の各 GAME の表示(優勝確率に含まれる)
- 種と試行の数の変更(固定)

## 前提

| # | 前提 | 崩れたときの影響 |
| --- | --- | --- |
| 1 | F-005 Task-1 が `data/public/winrates.json` を書く | 基準4 の「勝率のデータがありません」になる |
| 2 | F-001 の `simulate` が 10,000 回の試行を作者の PC のブラウザで 3 秒以内に終える | ページの表示が遅れる。試行の数を評価設定へ出すことを検討する |

## 非機能の要求

| 項目 | 要求 |
| --- | --- |
| 応答時間 | ページを開いてから結果の表示まで、作者の PC のブラウザで 3 秒以内 |
| 同時実行 | 考慮しない |
| 監査ログ | 表示に種・試行の数・計算日時を出す(基準3) |
