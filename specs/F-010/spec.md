# F-010 階級チームの強さと戦い方、全階級チームの総合評価

## 背景

価値責任者は、階級ごと(例: CC CORE)の評価は5人全体のチームとしての評価と特性であるべきだと述べた(2026-10-08)。オブジェクトをどれくらい優先するか、BOT ゲームか TOP ゲームか、先に集まるのかレーン戦を優先するのか、である。全階級(例: CC)の評価は、個人とチームの掛け合わせによる総合で、大会のルールに合わせて強い階級とコーチングをどう生かして一つのチームにできるかを示すべきだとも述べた。

この機能は ADR-0005 の3層の評価のうち、階級チームと全階級チームの層を作る。個人の層は F-009。

価値責任者は、階級チームの総合力にはメインコーチの実力も大きく関係すると述べた(2026-10-09)。例えば IT CORE のコーチ Eugeo は、過去の LTK の実績でも言語化力でもコーチとして高い水準にあり、IT CORE の底上げになっている。選手としての評価とコーチとしての評価は別物なので、階級チームに5つのレーンのロールとは別に「コーチ」の枠を設け、選手とは別の評価軸で評価し、総合力へ反映する。

## 用語

- **階級チーム**: あるチームのある階級の5人(例: CC CORE)
- **全階級チーム**: あるチームの3階級15人とコーチ(例: CC)
- **コーチの枠**: 階級チームの6人目の枠。担当コーチ(公式発表。MASTERS の選手が兼ねる)を置く。MASTERS の階級チームはコーチの枠を持たない
- **コーチの評価軸**(選手の8軸とは別): 指導の実績(LTK でのコーチのシーズン数と、担当した階級チームの成績の伸び)/ 言語化力(解説・配信・インタビューでの説明の質の根拠)/ 戦術とドラフトの設計(ドラフト・ウィークサイド・オブジェクトの方針の根拠)/ 選手時代の知見(プロ・大会の経歴)/ チームとの相性(担当する階級チームの弱い軸を補う知見の根拠)
- **強さの軸**: 階級チームの戦力 / 連携の厚み / 司令塔 / 継続性 / 指導 / ピックの幅 / フィアレス耐性
- **戦い方の特性**: 序盤型⇄終盤型 / レーン戦重視⇄集合重視 / 重心(TOP・JG・MID・BOT)/ オブジェクトの優先度 / 視界の管理。良し悪しではなく向きを示す
- **総合の軸**: Regular Stage の得点力 / MASTERS CUP の力 / エースの階級 / 階級の均衡 / コーチングの活用 / 一体感 / チーム設計(ウィークサイドの作り方)
- **ウィークサイド**: 資源(ゴールド・JG の支援)を他のレーンへ回すために、少ない資源で耐えることを任せるレーン。任せられる選手は安定感が高く、資源が少なくても崩れにくい
- **過去の LTK の試合の記録**: LTK3 の公開スプレッドシートの本番・スクリムの試合ごとの記録と、S1〜S3 の使用チャンピオン。集計値だけを出典つきで使う
- **継続の割合**: 階級チームの5人のうち、過去の LTK の記録に含まれる選手の割合

## 受入基準

### 階級チームの強さ

| # | 型 | 受入基準 |
| --- | --- | --- |
| 1 | ユビキタス | システムは階級チームの戦力を、5人の個人の軸(F-009 の表示の点数)を評価設定のロールごとの重み(初期値 MID 0.24 / JG 0.21 / SUP 0.21 / TOP 0.17 / ADC 0.17。価値責任者の指示「キャリーの MID が最も重く、チームの要になりやすい JG・SUP が次、中盤以降に試合を決める TOP・BOT が続く。差はわずか」)で合わせた値で計算しなければならない |
| 2 | ユビキタス | システムは階級チームの強さの軸を、同じ階級の4チームの中での相対評価(F-002 基準6 と同じ換算)で 0.0〜10.0 にしなければならない |
| 3 | ユビキタス | システムは司令塔の軸を、5人のコール力の最大値と、コール役が1人に定まっていることを示す出典つきの根拠から計算し、5人全員のコール力がデータなしの場合は「データなし」としなければならない |
| 4 | ユビキタス | システムは継続性の軸を、過去の LTK で同じチームかつ同じ階級で出場した選手の組の数から計算しなければならない |
| 5 | ユビキタス | システムは指導の軸を、コーチの枠に置いた担当コーチのコーチの評価軸の総合から計算しなければならない(選手としての評価は使わない) |
| 5b | ユビキタス | システムはコーチの評価軸を、それぞれ出典つきの根拠(LTK のコーチの実績、解説・配信・インタビュー、選手・視聴者の声、記事)から 0.0〜10.0 で計算し、根拠の無い軸は事前値(選手時代の経歴だけ)で計算して確度を「低」としなければならない |
| 5c | イベント駆動 | 階級チームのページを開いたとき、システムは5人の選手に並べてコーチの枠を表示し、コーチの評価軸のレーダーと根拠を表示しなければならない |
| 5d | ユビキタス | システムは階級チームの戦力に、コーチの評価の総合を評価設定の重み(初期値 0.15。選手5人の合計の重みを 0.85 に縮める)で加えなければならない |
| 6 | ユビキタス | システムはピックの幅の軸を、5人のピックプールと、同じチームの NEXT と CORE の得意チャンピオンの重なり(CORE は同じカードの直前の NEXT 戦で使われたチャンピオンを使えない規則)から計算し、重なりが多いほど低くしなければならない |

| 6b | ユビキタス | システムはフィアレス耐性の軸を、5人の大会のロールのピックプールの深さ(勝てるチャンピオンの数)と、同じシリーズで使ったチャンピオンを使えない規則(MASTERS CUP の決勝)で3試合を戦えるだけの重ならない得意チャンピオンの数から計算しなければならない |

### 階級チームの戦い方の特性

| # | 型 | 受入基準 |
| --- | --- | --- |
| 7 | ユビキタス | システムは戦い方の特性を、両端に名前の付いた目盛り(例: 序盤型 ⇄ 終盤型)で示し、優劣のレーダーに入れてはならない |
| 8 | ユビキタス | システムは序盤型⇄終盤型を、過去の LTK の試合の記録の 14 分までと 14 分以降のキル・アシストのペースの比と、14 分時点のチームのゴールド差から計算しなければならない |
| 9 | ユビキタス | システムはレーン戦重視⇄集合重視を、14 分時点のレーンのゴールド差の大きさと、14 分までのキル関与から計算しなければならない |
| 10 | ユビキタス | システムは重心を、チームのゴールドとダメージのロールごとの配分(過去の LTK の記録)と、5人の個人の地力・レーン戦の偏りから、TOP・JG・MID・BOT の割合として示さなければならない |
| 11 | ユビキタス | システムはオブジェクトの優先度と視界の管理を、5人のソロキューの対面との差の指標(F-009 の母集団で標準化)と、過去の LTK の記録、出典つきの記述から計算しなければならない |
| 12 | ユビキタス | システムは戦い方の特性の確度を、継続の割合と使った試合数から決め、過去の LTK の記録に含まれる選手が2人未満の階級チームでは、過去の LTK の記録を使わずに確度を「低」としなければならない |
| 12b | ユビキタス | システムは階級チームのウィークサイドの候補を、TOP・ADC・MID のうち安定感が最も高く、資源が少ない試合でも対面との差が崩れにくい選手のレーンとして示し、根拠(安定感の点数と対面との差)を付けなければならない |
| 13 | 状態駆動 | Finale のスクリム・本番の記録が入力されている間、システムはそれを過去の LTK の記録より優先して戦い方の特性を計算しなければならない |

### 全階級チームの総合

| # | 型 | 受入基準 |
| --- | --- | --- |
| 14 | ユビキタス | システムは Regular Stage の得点力を、NEXT と CORE の階級チームの強さから見込む「同じ日に両方勝つ確率」と各階級の勝率から計算しなければならない |
| 15 | ユビキタス | システムはエースの階級を、3階級の階級チームの強さの最大値と、その階級名で示さなければならない(特殊 BO4 の GAME 3 に置く候補) |
| 16 | ユビキタス | システムは階級の均衡を、3階級の階級チームの強さのばらつきが小さいほど高くなるように計算しなければならない |
| 17 | ユビキタス | システムはコーチングの活用を、MASTERS から CORE・NEXT へ出すコーチ(公式発表)の指導の軸の値と、担当する階級チームの最も弱い軸の改善の余地から計算しなければならない |
| 18 | ユビキタス | システムは一体感を、階級をまたいだ過去の共闘の組の数、チーム全体のリーダーを示す出典つきの根拠、NEXT と CORE の得意チャンピオンの重なりの少なさから計算しなければならない |
| 18b | ユビキタス | システムはチーム設計の軸を、各階級チームのウィークサイドの候補の確かさ(候補の選手の安定感と、二番目の候補との差)と、担当コーチがウィークサイドの作り方に通じていることを示す出典つきの根拠から計算しなければならない |
| 19 | イベント駆動 | 全階級チームのページを開いたとき、システムは総合の軸のレーダー、3つの階級チームの強さと戦い方の特性、エースの階級、F-001 のシミュレーションの優勝確率(入力の勝率表が F-005 のものである場合)を表示しなければならない |

### 共通

| # | 型 | 受入基準 |
| --- | --- | --- |
| 20 | ユビキタス | システムはすべての軸と特性に確度と根拠(計算に使った値・試合数・出典)を付け、根拠の無い軸と特性を「データなし」として数値を表示してはならない |
| 21 | ユビキタス | システムは過去の LTK の試合の記録を、集計値だけを出典つきで公開の画面に出し、第三者のスプレッドシートの生データを公開の配信物に含めてはならない |
| 22 | イベント駆動 | 階級チームの比較を開いたとき、システムは同じ階級の2チームの強さの軸と戦い方の特性を並べて示さなければならない(例: CC CORE と DD CORE) |

各基準には、違反すると失敗するテストが1つ以上必要です。

## スコープ外

- 試合ごとの勝率の推定(F-005)。この機能の軸は F-005 の入力になる
- ピックとチームの作戦の予想(F-006)
- Finale のスクリム・本番の記録の入力の手段(F-004)
- 個人の評価(F-009)

## 前提

| # | 前提 | 崩れたときの影響 |
| --- | --- | --- |
| 1 | 過去の LTK の記録の戦い方は、継続した選手の分だけ現在のチームに引き継がれる | 継続の割合が低い階級チームの特性は確度を下げる(基準12) |
| 2 | LTK3 の公開スプレッドシートの集計値の利用は、出典を示して集計値だけを使う範囲で認められる | 認められなければ、記事・視聴者の声の記述と Finale の記録だけで計算する |
| 3 | コーチの担当は公式発表のとおり(DD: CORE わしだい・NEXT たぬき忍者、CC: CORE Ceros・NEXT Yuhi、IT: CORE Eugeo・NEXT Enty、LR: CORE Recap・NEXT ねすてぃー) | 変更があれば入力を直す |

## 非機能の要求

| 項目 | 要求 |
| --- | --- |
| 応答時間 | 全チームの評価の計算が作者の PC で 5 秒以内 |
| 同時実行 | 考慮しない |
| 監査ログ | 評価の計算ごとに評価設定の版を残す |
