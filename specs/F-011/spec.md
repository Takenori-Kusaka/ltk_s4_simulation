# F-011 メタ解説の付録ページ

## 背景

価値責任者は、付録として現在の LoL のメタを深く知り、学べるページを求めた(2026-10-09)。各ロールの Tier の高いピックとそれが優先される理由、ゲーム全体で重要なオブジェクト、SUP はエンチャンターかタンクかメイジ・アサシンか、MID はサイドでのプッシュ力・一人で耐える力・オブジェクトへの集合のためのプッシュ力のどれが求められるか、を丁寧に説明する。ウィークサイドの考え方、ブルーサイドとレッドサイドの影響も載せる。各選手のメタに合う得意ピックを示し、「今のメタに強いのは誰か」と、それを選ぶ・選ばないというコーチの戦略が見えるようにする。勝率の計算がメタをどう使っているかの裏付けも、根本から丁寧に説明する。

一言でまとめるには根本を丁寧に説明しないと伝わらないため、専用のページにする。原稿の材料は `docs/research/meta-guide.md`(調査中)と `docs/research/meta-draft.md`。

## 用語

- **メタの一覧**: パッチごとのデータのファイル(`data/meta/<パッチ>.json` の形)。1件ごとに、ロール・数値の key・id・日本語名・段階・根拠の略号・出典の URL を持つ
- **段階**: メタの一覧の重要度。段階A(最重要)と段階B(重要)の2つ
- **メタの重要チャンピオン**: メタの一覧で段階A か段階B に当たるチャンピオン
- **メタに合う得意ピック**: 選手のピックプール(F-009)のうち、メタの重要チャンピオンに当たるもの
- **解説の原稿**: 章ごとの文章と出典。AI が書いた章には「AI 執筆」の印を章ごとに付ける
- **主張の根拠の印**: 原稿の主張ごとに付ける印。「出典の URL」「推定」「未確認」の3種類
- **大会のパッチ**: 大会で使われるパッチ番号。人が設定の値として入力する

## 受入基準

| # | 型 | 受入基準 |
| --- | --- | --- |
| 1 | イベント駆動 | メタ解説のページを開いたとき、システムは原稿の対象のパッチ番号と原稿の更新日を見出しの近くに表示しなければならない |
| 2 | ユビキタス | システムはロールごと(TOP・JG・MID・ADC・SUP)に、メタの一覧の段階A のチャンピオンをすべてと、段階B のチャンピオンをすべて、段階と、優先される理由(主張の根拠の印つき)とともに表示しなければならない。件数はメタの一覧にある件数とする |
| 3 | ユビキタス | システムはゲーム全体のオブジェクト(ドラゴン・ヴォイドグラブ・ヘラルド・バロン・タワーを含む)ごとに、現パッチでの重要度(段階か順位の値)と理由を表示しなければならない。重要度の値の無いオブジェクトがあれば、原稿の検証は失敗しなければならない |
| 4 | ユビキタス | システムは SUP の型(エンチャンター・タンク・メイジ・アサシン・ハイブリッド)と MID の役割(サイドでのプッシュ力・一人で耐える力・集合のためのウェーブ処理・ローム)の項目ごとに、現パッチでの重要度(段階か順位の値)と理由を表示しなければならない。重要度の値の無い項目があれば、原稿の検証は失敗しなければならない |
| 5 | ユビキタス | システムはウィークサイドの考え方(作る目的、任されやすいレーン、任された選手に求められること)と、ブルーサイドとレッドサイドの違い(ドラフトの順番、マップの差、勝率の差、LTK の過去のサイドごとの勝率)を表示しなければならない。出典で確かめられない値には「未確認」の印を付けて表示しなければならない |
| 6 | ユビキタス | システムは LTK 固有のドラフト規則(NEXT のプロテクト、CORE の使用禁止、MASTERS CUP のフィアレス)とメタの関係を表示しなければならない |
| 7 | イベント駆動 | メタの重要チャンピオンを選んだとき、システムはそのチャンピオンを F-009 のピックプールの条件(直近 120 日の評価の試合のうち大会のロールの試合だけ、チャンピオンごとに3試合以上)で持つ選手を一覧にし、試合数と縮小した勝率 (勝ち数 + 2.5) / (試合数 + 5) と選手のページへのリンクを付けなければならない |
| 8 | ユビキタス | システムはロールごとに、選手のメタに合う得意ピックを段階A は 2 点、段階B は 1 点として合計し、合計の上位 3 名をチームと階級とともに表示しなければならない。合計が同じ選手は名簿の順に並べなければならない |
| 9 | ユビキタス | 勝率の計算(F-005)の仕様が承認されるまで、システムは「勝率の計算はメタを使っていない」ことと、現在の入力(F-009 のピックプールの軸の式と入力)を表示しなければならない |
| 10 | ユビキタス | システムは原稿のすべての主張に、主張の根拠の印(出典の URL・推定・未確認のいずれか1つ)を付けなければならない。印の無い主張か、印を2つ以上持つ主張があれば、原稿の検証は失敗しなければならない。AI が書いた章には、章ごとに「AI 執筆」の印を付けなければならない |
| 11 | 状態駆動 | 大会のパッチが原稿の対象のパッチと異なる間、または大会のパッチの設定の値が空の間、システムは原稿が古い可能性を示す注意を表示しなければならない |
| 12 | ユビキタス | システムの画面は幅 360px のスマホと 1280px の PC で、横スクロールなしに本文を表示しなければならない(表は横に流せてよい) |

各基準には、違反すると失敗するテストが1つ以上必要です。

### 基準の補足

- 基準7・8 の選手のピックプールは `ratings.json` の `poolDetail` から読む。`poolDetail` のチャンピオンは数値の id で持つため、Data Dragon の `champion.json` の `key`(数値の文字列)で、メタの一覧の数値の key と突き合わせる。日本語名はメタの一覧の日本語名を使う
- 基準7・8 のデータは F-009 のピックプールと同じ計算の結果を使い、この機能で集計し直さない
- 基準9 は F-005 の仕様の承認の後に、メタの使い方の説明へ広げる(この仕様を改訂する)

## スコープ外

- メタの自動の更新(パッチごとの原稿の書き直しは人か AI の作業で行う)
- 試合ごとのピックの予想(F-006)
- 勝率の計算そのもの(F-005)。この機能は説明だけを持つ
- 大会のパッチの自動の取得(人が設定の値として入力する)

## 前提

| # | 前提 | 崩れたときの影響 |
| --- | --- | --- |
| 1 | 大会は各時点のライブのパッチで行われる(26.20〜26.23 の可能性) | パッチごとに原稿の更新が要る(基準11 で注意を出す) |
| 2 | プロとソロキューのメタの記述を、出典つきで要約できる | 出典で確かめられなかった主張は、「未確認」か「推定」の印を付けて載せる(基準10)。価値責任者の決定(2026-10-09) |
| 3 | 外部の記事は自分の言葉で要約し、数値と出典の URL を添えて載せる | 記事の文章を転載しない。見出しだけで確かめた記事は出典に数えない(その主張は「未確認」になる) |
| 4 | Riot Games の画像とアイコンをページに使わない | チャンピオンは日本語名の文字で示す。画像を使う場合はこの前提を改めてから仕様を改訂する |
