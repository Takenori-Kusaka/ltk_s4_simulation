# 前提の台帳

`docs/assumptions.md` として置きます。全ゲートの通過条件です。

このプロセスは、いくつかの前提が成り立つことを条件に組み立てられています。**前提が崩れたときに気づける状態**を保つのがこの台帳の目的です。

対象は、標準が置いている前提です。案件が独自に置いた前提は、機能仕様書の「前提」欄で扱います。**この台帳へ混ぜないでください**。

## この台帳は索引です

**対処の内容をここへ書かないでください**。前提への対処は既に標準の各章に規定があるため、台帳からは**参照するだけ**にします。再掲すると、規定の改訂が台帳へ伝わらず、食い違いが生じます。

リスク登録簿とも統合しません。前提は「成立しているか」で評価し、リスクは「確率と影響」で評価します。**評価の軸が異なります**。安全リスクアセスメント(テンプレ9)とも別の台帳です。

判断記録(ADR)とも統合しません。ADR は採用後に本文を書き換えませんが、**前提の充足状態は変化します**。

## 記入時の注意

- **充足状態を自己申告で決めないでください**。観測した事象の欄が空のまま AC-0 とした行は、記録として成立していません
- 「劣化時の進め方」には、前提が崩れた状態で**何を変えて進むか**を書きます。「注意して進める」は記述として認めません
- 受容の記録には**有効期限**を必ず書きます。期限のない受容は、恒久的な基準の引き下げになります
- 「対処の参照先」の欄に、対処の内容を書かないでください。**参照だけを書きます**

## 崩れたときの扱い

前提が崩れた場合、**その前提に依存していたゲートの構成を見直します**。ゲートをそのままにして運用を続けると、通過の記録だけが残ります。

見直しは `/process-change`(軸の入力や体制が変わる場合)、または判断記録(ADR)によります。
