# 選手の総合・階級チームの勝率・優勝確率の算出アルゴリズム(検証つきの起案)

F-009(個人の評価)と F-010(階級チームと全階級チームの評価)の数値を、勝率と優勝確率(F-005・F-001)へつなぐ算出方法の起案。`docs/design/team-model.md` 節5「より信頼できる算出方法の検討」の結果であり、同節1の「戦力」の重みと、節3の勝率の式(差 4 点で約 91%)を置き換える案を示す。

**この文書の式・初期値・推奨は AI の起案であり、価値責任者(価値判断)と技術判断者(G-3、ADR の採否)の確定を要する**。検証の数値は、節4 のスクリプトを実行した結果だけを書いた。推測で補った数値は無い。

価値責任者の要求(2026-10-08): 「ここのアルゴリズムは信頼性を必要とするもので、適当に 100% を配分すればいいって話じゃない」「選手の評価軸すべてを使って総合力が決まるべき」。ロールの重みの順序(MID > JG・SUP > TOP・ADC、差はわずか)は確定済みの方針として事前の値に使う。

## 0. 結論(要旨)

1. **過去の LTK で当たる見込みには上限がある**。NEXT・CORE の階級チームの真の強さのばらつきは、対数オッズで標準偏差 約 0.7(95% の範囲 0.2〜1.3)と推定した。強さを完全に知っていても、無作為に選んだ2チームの典型的な勝率は約 69% にとどまる。シーズン前に 80% を超える勝率を出すモデルは、過去の結果と合わない
2. **重みを LTK の勝敗から当てはめてはいけない**。8軸の重み・ロールの重みを勝敗に当てはめた案は、いずれも試合前の予測で当て推量(勝率 50%)より悪くなった(対数損失 +0.04〜+0.09)。係数の符号は標本でひっくり返り、ロールの重みは TOP と SUP が負になった。試合数(公式 123、スクリムを足しても約 200)では、8 個や 5 個の重みを決められない
3. **選手の総合は、8軸の等しい重み(各 1/8)を初期値にする**。等しい重みは「全軸を使う」を満たし、当てはめた重みより試合前の予測で悪くならなかった。ただし地力以外のデータの軸もランクの基準を含むため、等しい重みでもランクの基準が総合の約 35% を占める。これは隠さず、軸ごとの実効の重みとして表示する
4. **暫定式の勝率の尺度(差 4 点で 91%)は平らすぎる**。8軸の平均は中央の 5.0 に寄るため、チームの差が小さくなる。暫定式を当時の情報で再現すると、S3 で予測の勝率はほぼ 50〜55% に張り付いた。S2 で当てはめた尺度(1 点あたり対数オッズ 2.0。暫定式の約 3.5 倍)を S3 に使うと対数損失は 0.681 → 0.661 に下がった
5. **推奨は「試合前の評価(事前)+ 本番の結果による更新」の2段**。対数オッズ = β ×(戦力の差)+(結果から推定した補正の差)。β は1つだけで、4チームの勝率の広がりが過去の LTK と合うように決める。補正は Finale の結果(本番を重み 1、公開されればスクリムを重み 0.25)で試合日ごとに更新する。S3 で同じ形を試すと、対数損失 0.6475、Brier 0.2279(当て推量 0.6931・0.2500)で、比べた案の中で最も良かった。ただし差の 95% の範囲は 0 をまたぐ(試合数が 52 しかない)
6. **不確かさは、勝率の区間と、優勝確率の区間で示す**。選手の確度、β の範囲、補正の事後分布から強さを繰り返し引き、F-001 のシミュレーションを外側で回す

## 1. 選手の8軸から「選手の総合」を作る

### 1.1 検討した決め方

| 方法 | 性質 | この大会のデータでの結果(節4) | 判断 |
| --- | --- | --- | --- |
| 等しい重み(各 1/8) | 当てはめる値が無い。少ないデータで壊れにくい(「不適切な線形モデルの頑健さ」として知られる性質) | 当てはめた重みより悪くならない | **採る(初期値)** |
| 勝敗への説明力で重みを当てはめる(ロジスティック回帰) | 根拠がデータになる。重みの数だけ自由度がある | 試合前の予測で悪化(+0.041〜+0.094)。連携の係数が負(ブートストラップで 99% が負)。ランクの係数の符号が定まらない | 採らない |
| 等しい重みへ縮める当てはめ(事前分布 = 等しい重み、リッジ) | 階層ベイズの近似。データが十分なら重みが動く | 縮めても悪化(+0.029〜+0.045) | 採らない(Finale の後に再検討) |
| 主成分(第1主成分) | 軸の相関を考慮して1つにまとめる | 第1主成分はレーン戦・集団戦・連携・安定感に載り(負荷 0.35〜0.56)、地力・大会経験・コール力の負荷はほぼ 0(−0.11〜0.09)。全軸を使う要求に反する。予測も悪化(+0.022) | 採らない |
| ロール別のモデル(PandaSkill 型) | ロールごとに重みを持つ | 5 ロール × 8 軸 = 40 の重みはなおさら決められない | 採らない |
| 専門家の順序から重みを作る(順位重心法など) | 順序だけ決めれば重みが決まる | 8軸の順位重心法の重みは 0.34〜0.016 と急で、「全軸で」と合わない。未検証 | 価値責任者が軸に順序を付けたい場合の候補として残す |

### 1.2 推奨の式

```
選手の総合 O = 5.0 + Σ_k a_k × (x_k − 5.0)
  x_k : 8軸(地力・レーン戦・集団戦・連携・安定感・ピックプール・コール力・大会経験)の基礎の点数(F-009。0〜10)
  a_k : 軸の重み。初期値はすべて 1/8
```

- **0〜10 の絶対の物差しのまま合成する**。60 選手の中の相対評価(`rel()`)へ直してから合成しない。相対評価は、実際の差が小さくても 4 チームの間に差を作る(節5.3 の失敗の型 F2)
- **確度の低い軸は、F-009 の縮小(n / (n + k))で既にランクの基準へ寄っている**。総合の段階で二重に縮めない。代わりに、軸の確度から分散を持たせ、勝率の区間へ伝える(節2.4)

### 1.3 軸の相関と、実効の重みの表示

等しい重みでも、情報源ごとの効き方は等しくない。F-009 の式(データの軸 = ランクの基準 A × r + 5.0 × (1 − r) + 補正 + LTK の項)を展開すると、次のとおり。

| 情報源 | 総合への効き方(等しい重みのとき) |
| --- | --- |
| ランクの基準 A | 6 つのデータの軸の r の和 2.8 ÷ 8 = **0.35**(A が 1 点上がると総合が 0.35 点上がる) |
| ソロキューの対面との差(補正 P) | 6 つのデータの軸に 1/8 ずつ |
| LTK の経験 | 集団戦・連携・安定感の LTK の項(1 シーズン 0.4)× 3/8 = 1 シーズンあたり 0.15 点(上限 0.45)と、大会経験の軸 1/8 |
| 出典つきの根拠 | コール力 1/8 |

- S3 の選手の代理の指標(スクリムの 14 分のゴールド差・キル関与率・ダメージ割合・デス)は、選手単位で互いに相関した(レーン戦と集団戦 0.65、集団戦と連携 0.73、レーン戦と連携 0.60)。ランク・大会経験・コール力とは相関が小さかった(絶対値 0.30 以下)。つまり8軸は「試合の働き」「ランク」「経験」「根拠」のおよそ4つの情報源からなる
- **推奨**: 選手のページに「総合の内訳」として、上の4つの情報源の実効の寄与を示す。価値責任者が重みを変えるときは、軸の重みではなく、この実効の寄与を見て決める(例: ランクの実効 0.35 を下げたいなら、データの軸の r を下げる)

### 1.4 調子の係数の掛け方(確認事項)

ADR-0004 は「表示の点数 = 基礎の点数 × 調子の係数(0.90〜1.10)」とした。0〜10 の点数にそのまま掛けると、8 点の選手は ±0.8 点、3.4 点の選手は ±0.34 点動き、上手い選手ほど調子の影響が大きくなる。勝率は差で決まるため、階級の高い選手の調子が過大に効く。**シミュレーションの入力では「5.0 + (基礎の点数 − 5.0) × 係数」か、係数を総合への加算(±0.5 点など)に読み替える案を推奨する**(技術判断者の確定事項)。調子の効果は過去のデータで検証していない。

## 2. 階級チームの強さと、階級チーム同士の勝率

### 2.1 戦力(階級チームの強さ)

```
戦力 S = Σ_r w_r × O_r
  w_r : ロールの重み。MID 0.24 / JG 0.21 / SUP 0.21 / TOP 0.17 / ADC 0.17(価値責任者の順序。初期値のまま)
```

- ロールの重みは、データでは見分けられなかった。等しい重みと暫定の重みの差は、S2・S3 の選手単位の Elo で対数損失 0.6676 対 0.6695、S3 のスクリムを含む試合で 0.6986 対 0.6981 だった。当てはめた重みは悪化した(+0.070)。**価値責任者の順序を事前の値として尊重し、データで動かさない**
- F-010 の他の強さの軸(連携の厚み・司令塔・継続性・指導・ピックの幅・フィアレス耐性)は、**勝率の式に入れない**。コール力は既に選手の総合に入っており、司令塔として足すと二重に数える。継続性(過去に同じチームで共闘した組の数)は、S3 の係数が負(−0.32〜−0.60)で、符号が定まらなかった。これらは「なぜその強さか」を説明する表示に使う

### 2.2 勝率の見込み

```
対数オッズ logit p(A が B に勝つ) = β × (S_A − S_B) + (θ_A − θ_B)
  β   : 戦力の差を勝率へ写す尺度(1 つだけ)
  θ   : 結果から推定する補正。事前分布 θ ~ 正規(0, σ²)
  サイドの補正: 0(RS のブルーの勝率は 72 試合で 47.2%。S1 37.5%、S2 45.8%、S3 58.3% と向きが定まらない)
```

**β の決め方(広がりを合わせる)**:

- 過去の LTK では、強さの差の広がりのうち試合前の情報で説明できたのは一部だった。S3 で、S2 から当てはめた尺度(1 点あたり 2.0)を使うと、予測の対数オッズの差の標準偏差は 0.356 だった。真の強さの差の標準偏差は √2 × 0.7 = 0.99 なので、比は約 0.36
- そこで **β は、同じ階級の 6 組の (S_A − S_B) について、β × 差の標準偏差が 0.35 になる値にする**(感度の範囲 0.2〜0.6)。軸の定義や補正の有無で S の広がりは変わるため、点数あたりの固定の値(「差 4 点で 91%」など)は使わない
- 参考: 暫定式のうち計算できる部分(ランクの基準で決まる軸、大会経験、コール力、LTK の項。ソロキューの補正は 0)で Finale の戦力を作ると、階級内の最大差は 0.39〜0.49 点だった。暫定の尺度では最も有利なチームでも勝率 0.506〜0.570、1 点あたり 2.0 なら 0.521〜0.727 になる

**補正 θ の更新**:

- 事前分布の幅 σ = 0.58(リッジの強さ λ = 1/σ² = 3)。S3 の試験で λ = 3 が λ = 1 より良かった。この値は、真の強さの幅 0.7 のうち試合前の情報で説明できない残り(0.7 × √(1 − 0.36²) ≈ 0.65)とおおむね合う
- データ: Finale の本番の結果(重み 1)。スクリムの記録が LTK3 と同じ形で公開されたら重み 0.25 で足す。リスナーとのスクリムは、階級ごとに1つの仮のチームとして扱う
- 方法: 対数オッズに β × (S_A − S_B) を固定の項として入れた Bradley-Terry を、試合日ごとに当て直す(Elo の逐次更新と同じ働き。S2・S3 で K = 32〜64 が最も良かった)
- 代打(各チーム 1 名)が出た試合は、その試合だけ代打の選手の総合(無ければ階級とロールの中央値)で S を作る

### 2.3 MASTERS の扱い

MASTERS の強さの幅は 2.1 と推定したが、試合は S3 の 20 だけで、95% の範囲は 0.4〜探索範囲の上限 2.5 と広い。NEXT・CORE と同じ式と初期値(β の決め方、λ = 3)で始め、MC の結果で更新する。S3 で同じ形を試した MASTERS の対数損失は 0.669(当て推量 0.693)だった。フィアレス(同じ BO3 の中で使ったチャンピオンを使えない)の効果は、この式に入っていない。

### 2.4 不確かさの表し方

| 不確かさの源 | 表し方(初期値は AI の起案) |
| --- | --- |
| 選手の軸の確度 | 確度「高・中・低・推定」に、点数の標準偏差 0.5・1.0・1.5・2.0 を割り当て、S の分散 Σ w_r² Σ a_k² σ_k² へ伝える |
| β | 対数オッズの差の標準偏差 0.2〜0.6 に当たる範囲から一様に引く |
| θ | 当て直した Bradley-Terry の事後分布(ラプラス近似: ヘッセ行列の逆行列) |

- 勝率は「点の値 + 80% の区間」で示す。区間は上の3つから強さを 1,000 回引いて作る
- **常識の検査に足す候補**(価値責任者が確定する): K-08「Finale の結果が入る前に、NEXT・CORE で勝率 0.80 を超える組が無い」(真の強さの幅の 95% の上限 1.3 から、典型的な差の勝率は約 0.81)。K-09「階級ごとの 6 組の勝率が、すべて 0.45〜0.55 に収まっていない」(平らすぎる失敗の型 F1 の検出)

## 3. 全階級チームの総合と優勝確率への接続

1. 階級ごとの勝率表(NEXT・CORE・MASTERS の 4 チームの全組)を、節2の式で作り、F-001 の `stageWinTables` に渡す。RS・MC・Playoffs で同じ式を使う(ステージ別の差を示すデータは無い)
2. **同日の両勝ちの +1pt**: F-001 は NEXT と CORE の試合を独立に引く。過去の RS の 36 カードで、同じチームが両方勝ったのは 20(55.6%)で、各シーズンの最終的な強さから独立を仮定して見込む数 18.9 と差は小さい。**独立の仮定のままでよい**(チーム全体の調子のような共通の効果は、データで見えなかった)
3. **MASTERS CUP**: MASTERS の勝率表で F-001 が順位点を模擬する
4. **特殊 BO4 の GAME 3(2pt)**: 上位シードが階級順を選ぶ方策(F-001 の `strongest-g3` など)に、この勝率表を渡す。S3 では上位シードが GAME 3 に置いた階級は 4 マッチ中 3 で NEXT だった(format-history 節3.5)。方策は設定で切り替え、優勝確率への影響を感度として示す
5. **優勝確率の区間**: 外側で強さを 200 回引き(節2.4)、内側で F-001 を 2,000 回回す。優勝確率は中央値と 80% の範囲で示す
6. **全階級チームの総合の軸**(ADR-0005 決定6「シミュレーションと同じ入力から作る」): Regular Stage の得点力は F-001 の RS の期待得点、MASTERS CUP の力は MC の期待得点、エースの階級は 3 階級の (S − 階級の平均) × β の最大、から作る。総合の軸を別の式で作らないことで、総合の順位と優勝確率の食い違いを防ぐ

### 5.2 データが増えたときの更新(Finale のスクリム・本番)

1. **本番の試合日ごと**: その日までの本番の結果で θ を当て直し、勝率表と優勝確率を作り直す。β と重みは動かさない
2. **スクリムの記録が公開されたら**: 重み 0.25 で θ の当て直しに足す。選手ごとの指標(14 分のゴールド差など)は、軸の点数にも勝率にも直接は足さない(節4.4 で予測しなかった)。戦い方の特性(F-010 節2)の材料に使う
3. **RS の 3 日目の後**: 記録した試合前の予測について、対数損失を「当て推量」「結果だけ」と比べる。事前の項が結果だけより悪ければ、β を感度の下限(0.2)へ下げる。上げる向きの変更はしない(過信の防止)
4. **代打・ロスターの変更**: その試合の S を作り直す。θ は階級チームに付けたまま残す
5. **Finale の後**: S1〜S4 の公式とスクリムで、β の決め方と λ を見直す。軸やロールの重みの当てはめは、公式の試合が数百になるまで行わない

### 5.3 信頼性を損なう失敗の型と防ぎ方

| # | 失敗の型 | 起こる仕組み | 防ぎ方 |
| --- | --- | --- | --- |
| F1 | 平らすぎる(全チームほぼ 50%) | 多くの軸の平均が 5.0 に寄り、点数あたり固定の尺度で写す(暫定式で確認) | β を広がりで決める。K-09 で検出 |
| F2 | 尖りすぎる(80〜90% が並ぶ) | 4 チームの相対評価(`rel()`)を勝率に使う。相対評価はわずかな差を 0〜10 に引き伸ばす。または強さの軸を足して二重に数える | 勝率には相対評価の前の値を使う。司令塔などを足さない。K-08 で検出 |
| F3 | 重みの過学習 | 100〜200 試合で 8 や 5 の重みを当てはめる(係数の符号が逆転、ロールの重みが負) | 重みは事前の値で固定し、当てはめるのは β と θ だけ |
| F4 | 隠れた二重計上 | データの軸がランクの基準を共有し、ランクが総合の 35% を占める。コール力を総合と司令塔の両方で数える | 実効の寄与を表示する(節1.3)。司令塔は表示だけ |
| F5 | 先読み(検証の水増し) | 結果を知った後の根拠・ランク・同じ日のスクリムを、試合前の情報として使う | 検証と更新は「その試合より前の日付」の情報だけ。根拠に日付を必須にする |
| F6 | 見かけの関係 | キル関与率のように、負けている側で高くなる指標を勝敗に当てはめる | 試合の指標を勝敗の予測へ直接入れない。F-009 の対面との差で使う |
| F7 | スクリムの過信 | スクリムは試す場で、相手(リスナー)の強さも分からない | 重み 0.25。リスナーは仮のチームとして分ける |
| F8 | 階級の違いを無視する | MASTERS の強さの幅は NEXT・CORE と違う可能性がある | 階級ごとに β を決める。MASTERS は結果で早く更新する |
| F9 | 不確かさを見せない | 点の値だけを出すと、52 試合の検証の幅が伝わらない | 勝率と優勝確率に 80% の区間を付ける |

### 5.4 採らなかった案と理由

| 案 | 採らなかった理由 |
| --- | --- |
| 8軸の重みを LTK の勝敗で当てはめる(ロジスティック回帰・機械学習) | 試合前の予測で +0.041〜+0.094 悪化。係数の符号が標本で変わる(節4.4) |
| 階層ベイズ(等しい重みへ縮める当てはめ) | 縮めても +0.029〜+0.045 悪化。Finale の後、試合が増えたら再検討する |
| 主成分で合成する | 第1主成分が地力・大会経験・コール力をほぼ捨てる。「全軸を使う」に反し、予測も悪化 |
| ロールの重みを当てはめる | TOP・SUP が負になる。予測が +0.070 悪化 |
| 暫定の尺度「差 4 点で約 91%」 | S3 で勝率が 50〜55% に張り付き、尺度を当てはめた案より悪い(0.6806 対 0.6606) |
| 前シーズンまでの LTK の勝敗を選手の強さに使う | S2 で向きが逆。チームの成績で、選手の力を表さない |
| 継続性・司令塔などを勝率に足す | 継続性は係数の符号が定まらない。司令塔はコール力の二重計上 |
| 選手の Elo をシーズンをまたいで持ち越す | 階級チームの Elo とほぼ同じ(0.6734 対 0.6697)で、実装が重い |
| チームの強さを最強の1人(MAX)で代表させる(ソロキューの研究) | 大会ではロールの補完が効く(rating-methods.md 節3)。この検証では試していない |
| サイドの補正 | RS のブルーの勝率に一貫した向きが無い |
| 同日の NEXT と CORE に共通の効果を入れる | 両勝ちの頻度が独立の見込みと合う(20 対 18.9) |
