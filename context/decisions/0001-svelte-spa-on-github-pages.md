# ADR-0001: GitHub Pages の SPA を TypeScript + Vite + Svelte で作る

## ステータス

提案(2026-10-08)。技術判断者 takenori-kusaka が会話で「TypeScript + Vite + Svelte」を選択済み。採用は G-3 の判定記録で確定する。

## コンテキスト

価値責任者は、スマホと PC から GitHub Pages の SPA を操作し、予測・考察・根拠を見て大会当日までに楽しみたいと述べた(2026-10-08)。パラメーターを動かすとブラウザ内で優勝確率を再計算できることが望ましい。開幕は 2026-10-15 で、残り1週間で最小機能を動かす必要がある。プロセス構成のスタックは `undetermined` のままで、SG-0 までに確定する。

## 決定

- 言語は TypeScript。ビルドは Vite。UI は Svelte
- シミュレーションの計算(得点・順位・シード・モンテカルロ)も TypeScript で書き、ブラウザとローカルの Node の両方で同じコードを動かす
- 成果物は静的ファイルとして GitHub Pages へ配置する。サーバーは持たない
- プロセス構成のアダプタは `node` へ切り替える(`/process-change` 種別 settings。この ADR の採用後)

## 検討した選択肢

| 案 | 性質(AI が整理) | 採らなかった理由 |
| --- | --- | --- |
| TypeScript + Vite + React | 部品とグラフの部品が最も多い。バンドルは Svelte より大きい | 性質欄の短所を不採用の理由とする(技術判断者 takenori-kusaka が 2026-10-08 に「採らなかった理由は明確」と述べ、性質欄の記述を理由として採用したものを転記) |
| Python で計算し静的 HTML を生成 | 統計ライブラリが使える。ブラウザ内の即時再計算には別途 JS が要り、2言語になる | 性質欄の短所を不採用の理由とする(技術判断者 takenori-kusaka が 2026-10-08 に「採らなかった理由は明確」と述べ、性質欄の記述を理由として採用したものを転記) |

## 可逆性

| 項目 | 内容 |
| --- | --- |
| 後から変えられるか | 変えにくい(UI の部品は書き直しになる)。計算部分は UI から分けておけば再利用できる |
| 変えるとしたら必要なこと | UI 層の書き直し。計算部分は純粋な TypeScript のモジュールに保つ |
| いつまでなら安く変えられるか | 最初の画面の実装が入る前(開幕前の最初の機能 PR まで) |

## 非機能への影響

| 項目 | 影響 |
| --- | --- |
| 性能 | モンテカルロの試行回数はブラウザの CPU に依存する。スマホで重い場合は Web Worker と試行回数の調整で対応する |
| 可用性 | GitHub Pages の可用性に従う。サーバーを持たない |
| セキュリティ | 静的配信のみ。API キーをバンドルに含めてはならない(ADR-0002) |
| 運用 | Node の依存の更新が要る |

## 事業への影響

| 項目 | 内容 |
| --- | --- |
| 影響を受ける利用者・業務 | 作者本人。画面が開けない、遅いと楽しめない |
| 顕在化が分かる兆候 | スマホでの初回表示や再計算が数秒以上かかる。Svelte で必要な部品が見つからず自作が増える |
| 回復に要する時間 | 計算部分を残して UI を差し替えるなら 2〜5 日 |
| 取り消しの可否 | 人手で戻せる |
| 影響する必達基準 | 該当なし |

## 影響

- 計算と UI を分けるため、計算モジュールは Node のテストで検証できる
- この決定は、データの取得方法と更新の仕組みを決めない(ADR-0002)
