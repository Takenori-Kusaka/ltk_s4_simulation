# ADR-0005: 評価を「個人・階級チーム・全階級チーム」の3層にし、階級チームは戦い方の特性、全階級チームは大会のルールに合わせた総合で評価する

## ステータス

提案(2026-10-08)。方針は価値責任者 takenori-kusaka の指示(2026-10-08)による。採用は G-3 の判定記録で確定する。

## コンテキスト

価値責任者の指示(2026-10-08、要旨):

- 個人の評価軸は、チームゲームの能力の評価値でよい(ADR-0004 の8軸。「引き出し」は「ピックプール」と呼ぶ)
- CORE や NEXT といった階級ごとの評価は、5人全体のチームとしての評価と特性であるべき。オブジェクトをどれくらい優先するか、BOT ゲームか TOP ゲームか、先に集まるのかレーン戦を優先するのか
- CC や LR といった全階級の評価は、個人とチームの掛け算による総合評価であるべき。この大会のルールに合わせて、強い階級やコーチングをどう生かして一つのチームにできるか

F-002 Task-3 のチームのページは、階級ごとに個人の軸の平均を4チームの相対評価で示すだけで、チームとしての戦い方を表さない。

使えるデータ:

- 個人の評価(F-009)
- LTK3 の公開スプレッドシート(本番・スクリムの試合ごとの KDA・KP・CS・ダメージ・ゴールド、14 分時点のゴールド差・チームのゴールド差・キル関与、14 分前後のキルとアシストのペース)。Finale でも同じ形の記録が公開されれば、スクリムの結果として使える
- 過去の LTK の使用チャンピオン(S1〜S3、調査で解析済み)
- 公式発表のロスターとコーチ、過去シーズンの同じチームでの共闘の記録(調査)
- 記事・視聴者の声によるチームの戦い方の記述(出典つき)

## 決定

1. **評価を3層にする**
   - **個人**(ADR-0004): 地力 / レーン戦 / 集団戦 / 連携 / 安定感 / ピックプール / コール力 / 大会経験。調子は係数
   - **階級チーム**(例: CC CORE の5人): 強さの軸と、戦い方の特性の2面で示す
   - **全階級チーム**(例: CC): 個人と階級チームの掛け合わせに、大会のルール・コーチング・一体感を加えた総合で示す
2. **階級チームの強さの軸**(レーダー、4チームの相対評価)
   - 戦力: 5人の個人の軸からロールの重みで作る総合の力
   - 連携の厚み: 5人の連携・集団戦と LTK の経験
   - 司令塔: コール力の最も高い選手の値と、コール役が1人に定まっているか(根拠つき)
   - 継続性: 過去の LTK で同じチームで共闘した組の数
   - 指導: 担当コーチの経歴と、チームの弱い軸を補える知見(根拠つき)
   - ピックの幅: 5人のピックプールと、同じ日の NEXT との使用チャンピオンの重なり(CORE の使用禁止の規則)
3. **階級チームの戦い方の特性**(良し悪しではなく、向きを示す両極の目盛り)
   - 序盤型 ⇄ 終盤型: 14 分までと 14 分以降のキル・アシストのペースの比、14 分時点のチームのゴールド差
   - レーン戦重視 ⇄ 集合重視: 14 分までのレーンのゴールド差の大きさと、序盤のキル関与(先に集まる)
   - 重心(TOP / MID / BOT / JG): チームのゴールドとダメージの配分、個人の地力・レーン戦の偏り
   - オブジェクトの優先度: ドラゴン・バロン・ヘラルド・タワーへの関与(過去の LTK、ソロキュー)と出典つきの記述
   - 視界の管理: 5人の視界の指標
   - 材料が無い特性は「データなし」にする。過去の LTK の記録は、ロスターの継続した選手の分だけを使い、継続の割合を確度にする。Finale のスクリム・本番の結果が入ったら優先して使う
4. **全階級チームの総合の軸**(大会のルールに合わせる)
   - Regular Stage の得点力: NEXT と CORE の両方の勝率(同じ日に両方勝つと +1pt の規則)
   - MASTERS CUP の力: MASTERS の階級チームの強さ
   - エースの階級: 特殊 BO4 の GAME 3(2pt)に置ける最も強い階級の強さ
   - 階級の均衡: 3階級の強さのばらつきの小ささ(シード争いの安定)
   - コーチングの活用: MASTERS から CORE・NEXT へ出すコーチが、その階級の弱い軸を補えるか
   - 一体感: 階級をまたいだ過去の共闘、リーダーの存在、ピックの重なりの少なさ(CORE の使用禁止の規則)
   - 優勝確率: F-001・F-005 のシミュレーションの結果(総合の結論として別に示す)
5. **すべての軸と特性に、確度と根拠を付ける**(ADR-0004 と同じ原則)。根拠の無い特性・軸は数値にしない
6. **全階級の総合は、シミュレーション(F-005・F-001)と同じ入力から作り、食い違わないようにする**

## 検討した選択肢

| 案 | 性質(AI が整理) | 採らなかった理由 |
| --- | --- | --- |
| 階級チームを個人の軸の平均だけで示す(F-002 Task-3 の現状) | 単純。チームとしての戦い方や相性を表せない | 価値責任者の指示(2026-10-08)により改める(AI が転記) |
| 全階級チームを3階級の平均で示す | 単純。大会のルール(同日の両勝ちの加点、特殊 BO4 の GAME 3)とコーチングを表せない | 価値責任者の指示(2026-10-08)により改める(AI が転記) |
| 戦い方の特性を優劣のレーダーにする | 他の軸と同じ見た目。序盤型と終盤型に優劣は無く、誤解を招く | 性質欄の短所を不採用の理由とする(技術判断者 takenori-kusaka が 2026-10-09 に、ADR-0001・0002 と同じ扱いで転記することを了承したものを転記) |

## 可逆性

| 項目 | 内容 |
| --- | --- |
| 後から変えられるか | 変えられる。軸と特性の定義は設定に置く |
| 変えるとしたら必要なこと | 設定と画面の変更 |
| いつまでなら安く変えられるか | 勝率の推定(F-005)が階級チームの軸を入力に使い始める前 |

## 非機能への影響

| 項目 | 影響 |
| --- | --- |
| 性能 | 影響なし(集計時に一度計算する) |
| 可用性 | 影響なし |
| セキュリティ | 影響なし |
| 運用 | LTK3 のスプレッドシートの取り込み(第三者の著作物のため、集計値だけを出典つきで使い、生データは公開しない)。Finale のスクリム・本番の記録の入力(F-004) |

## 事業への影響

| 項目 | 内容 |
| --- | --- |
| 影響を受ける利用者・業務 | 作者本人。チームの比較と勝率の予測の納得感 |
| 顕在化が分かる兆候 | 実際の試合の戦い方(序盤型・重心)が特性と食い違う。総合の順位と優勝確率が食い違う |
| 回復に要する時間 | 設定の調整なら数時間、軸の見直しなら 1〜2 日 |
| 取り消しの可否 | 人手で戻せる |
| 影響する必達基準 | 該当なし |

## 影響

- 新しい機能 F-010(階級チームと全階級チームの評価)を作る。F-002 Task-3 のチームのページは F-010 の表示へ置き換わる
- F-005(勝率の推定)は、個人(F-009)と階級チーム(F-010)の評価を入力にする
- 視界・オブジェクト・マクロ(ADR-0004 でチームの指標にしたもの)は、階級チームの特性の中に入る
