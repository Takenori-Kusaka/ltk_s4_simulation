# ADR-0003: シミュレーションの入力を「時点 × 定量・定性」で分類し、すべての値と点数に根拠を付ける

## ステータス

提案(2026-10-08)。方針は価値責任者・技術判断者 takenori-kusaka の要望(2026-10-08)による。採用は G-3 の判定記録で確定する。

## コンテキスト

価値責任者は、大量のデータと情報に裏付けられた根拠のあるシミュレーションを求めた(2026-10-08)。入力には、数値で分かるもの(得意ピック・LTK のピック・勝率・CS・最高ランク・現在ランク)と、定性的なもの(IGL 力・コール力・性格・メンバー相性・コーチ・対面との相性・成長ポテンシャル)が混ざる。LoL のメタ(現パッチ、Worlds のメタ、Tier の高いチャンピオン、特殊なビルド、マクロの流行)も入れる。スコアリングには根拠と解説を付けたい。

op.gg などの画面の自動取得は ADR-0002 で採らない。過去のデータは、調べた時点の値を出典つきで静的に確保する。

## 決定

1. **入力を時点で3つに分ける**
   - 静的(過去): 過去の LTK 戦績とピック、最高ランク、得意ピック、調査時点の戦績サイトの数値。調査のスナップショットとして出典 URL と取得日つきで保存する
   - 現在: 現在ランク、直近の試合、チャンピオン別の成績(Riot API)、ロール、チームの構成、コーチ、対面、メタ(パッチノート、Worlds のメタ、Tier、ビルド、マクロの流行)
   - 未来: スクリムの結果、本番の試合結果(入力されるたびに増える)
2. **すべての値を同じ形で持つ**: 値、出典(URL・API・手入力・調査の文書)、取得日、確度(高・中・低)、書いた主体(人 / Riot API / AI の調査・分析と、そのモデル名)
3. **定性の評価は 0〜10 の点数と根拠の文章の組で持つ**。根拠の文章の無い定性の点数は入力として受け付けない。AI が付けた点数は、画面で「AI の評価」と明示し、人が上書きできる
4. **採点の式と重みは設定ファイルに置き、画面で根拠として開ける**。5軸の点数、勝率、ピックの見込みは、どの入力をどの重みで使ったかを辿れる形で出す
5. **AI の文章(作戦の予想・解説)は数値の計算に使わない**(ADR-0002 の決定4 と同じ)。ただし、AI が出典つきで付けた定性の点数(決定3)は計算に使える。この区別をデータの「書いた主体」で行う

## 検討した選択肢

| 案 | 性質(AI が整理) | 採らなかった理由 |
| --- | --- | --- |
| 定量の数値だけで採点する | 再現性が高く、根拠が明確。IGL 力・相性など価値責任者が求めた定性の要素を表せない | 性質欄の短所を不採用の理由とする(技術判断者 takenori-kusaka が 2026-10-08 に「採らなかった理由は明確」と述べ、性質欄の記述を理由として採用したものを転記) |
| 機械学習のモデルで勝率を直接推定する | 過去の LTK の試合数(S1〜S3 で約120試合)が学習に足りない。根拠の説明が難しい | 性質欄の短所を不採用の理由とする(技術判断者 takenori-kusaka が 2026-10-08 に「採らなかった理由は明確」と述べ、性質欄の記述を理由として採用したものを転記) |
| 定性の評価を根拠なしの手入力の点数で持つ | 入力が速い。根拠を示すという要望に反する | 性質欄の短所を不採用の理由とする(技術判断者 takenori-kusaka が 2026-10-08 に「採らなかった理由は明確」と述べ、性質欄の記述を理由として採用したものを転記) |

## 可逆性

| 項目 | 内容 |
| --- | --- |
| 後から変えられるか | 変えにくい。データの形(値・出典・取得日・確度・主体)は全機能が読む |
| 変えるとしたら必要なこと | 全データの移行と、F-002・F-005・F-006 の読み込みの変更 |
| いつまでなら安く変えられるか | F-002 Task-1(指標ファイルの型)のマージまで |

## 非機能への影響

| 項目 | 影響 |
| --- | --- |
| 性能 | 値ごとに出典を持つため、データの量が数倍になる。60選手規模では問題にならない見込み |
| 可用性 | 影響なし |
| セキュリティ | 出典に API キーや個人の連絡先を含めない |
| 運用 | 定性の評価の更新に、人か AI の調査の手間が掛かる |

## 事業への影響

| 項目 | 内容 |
| --- | --- |
| 影響を受ける利用者・業務 | 作者本人。根拠が辿れないと、予測を楽しむ材料にならない |
| 顕在化が分かる兆候 | 出典の無い値が増える。画面で根拠を開いても「出典なし」が出る |
| 回復に要する時間 | データの形を直すなら 1〜3 日 |
| 取り消しの可否 | 人手で戻せる |
| 影響する必達基準 | 該当なし |

## 影響

- F-002 の指標ファイルの型は、この形に従う(F-002 Task-1 で実装する)
- F-003 が静的・現在のデータの収集、F-004 が未来のデータの入力を担う
- 調査で集めた `docs/research/` の値は、この形へ移す作業が要る
