# ADR-0004: 選手の評価をチームゲームの働きの8軸で作り、データは「ランクの基準 + 対面との差」、根拠の無い軸は数値にしない

## ステータス

提案(2026-10-08)。方針は価値責任者 takenori-kusaka の要求(2026-10-08「コールできないのにコール力が高い、マクロを分かっていないのにマクロが高い、が目に付いた瞬間すべての信頼を失う」「軸は 6〜8 に増やしてよい」「データが無い選手はランク帯・LoL 歴・サモナーレベルからおおよその中央値に」)による。採用は G-3 の判定記録で確定する。

## コンテキスト

F-002 の採点(5軸、固定の範囲で線形に換算)を 60 選手の実データにかけたところ、次の誤りが出た(2026-10-08)。

- SUP と JG の「レーン戦」が 10.0 に張り付く(CS の換算範囲がロールに合っていない)
- Master の ADC でも「チームファイト」が 3.8(キル関与率とダメージ割合の範囲がソロキューの実際の値より高い)
- 「プールとメタ適合」が使ったチャンピオンの数そのもの(得意を絞る選手ほど低い)
- 「コール・大会経験」が全員データなし

実データの分析(`docs/research/rating-methods.md` と同時期の作業。60 選手 × 約30試合、参加者のべ 16,490 人分)で、次が分かった。

- ソロキューで大会のロールを遊んでいない選手がいる(SHAKA の TOP は 29 試合中 2、Rainbrain の JG は 2、アステル・レダの JG は 3)
- 試合の新しさがばらつく(直近 60 日の試合が 0 件の選手が 7 名。前シーズンの試合も混ざる)
- 同じ試合の対面との差の指標(最大 CS 差、視界の差、対面比のダメージ)はランクとほぼ無相関(相関 0.10、−0.02、0.24)。ソロキューは同じ MMR 帯で組まれるため、対面との差は「自分のランクより強いか」を表す
- 既存の評価システム(Mobalytics GPI・OP.GG OP Score・DEEPLOL AI Score)と学術モデル(PandaSkill・SIDO)は、どれも「マクロ」「コール」を数値にしていない。学術モデルは、ロール別の評価、ロール内のパーセンタイル、試合数の少ない選手の平均への縮小、保守的な下限の表示を共通に使う

## 決定

価値責任者の指示(2026-10-08)により、当初の起案(メカニクス・視界・オブジェクトを個人の軸に含む8軸)を次のとおり改めた。「メカニクスは日本人にとって直感的でない」「オブジェクトと視界はチームゲームの LoL では個人の評価になりにくく、チームの評価ならあり」「直近の勢いは軸ではなく個人の状態として、各軸の数字に係数がかかる」。

1. **個人の軸を 8 にする**(データの軸 6 + 根拠の軸 2)。チームの中で個人が果たす働きを測る
   - **地力**: その選手の基礎の実力。ランクの基準が最も強く効く
   - **レーン戦**: 対面とのレーンの勝ち負け(JG は序盤のジャングル、SUP は序盤の関与と視界の差)
   - **集団戦**: 集団戦での役割の遂行(キャリーはダメージ割合、前衛はダメージを受けた割合、行動妨害)
   - **連携**: 味方を活かす力(キル関与率、味方と取ったキル、味方を救った回数、回復・シールド)
   - **安定感**: 崩れにくさ(対面よりデスが少ないか、試合ごとの出来のばらつきが小さいか)
   - **ピックプール**: 大会のロールで勝てるチャンピオンの幅(3 試合以上遊んだチャンピオンの数と、その勝率)
   - **コール力**(根拠の軸): 出典つきの根拠から作る
   - **大会経験**(根拠の軸): LTK の過去の出場と勝敗、他の大会、プロの経歴から作る
2. **視界・オブジェクト・マクロはチームの評価にする**: チームのページで、所属選手の試合の値と、マクロの定性の根拠から、チーム単位の指標として示す。個人のレーダーには入れない
3. **調子は軸ではなく、各軸に掛かる係数にする**: 直近 14 日の評価の試合の勝率(試合数で縮小)、ランクの LP の増減、試合数(練習量)から 0.90〜1.10 の係数を作る。選手の状態として画面に示し、各軸の表示の点数とシミュレーションの入力は「基礎の点数 × 調子の係数」とする。基礎の点数も説明に示す
4. **データの軸の点数 = ランクの基準 + 対面との差による補正(試合数で縮小)**
   - ランクの基準: 現在のソロランク(無ければ最高ランク、それも無ければ事前値)を 0〜10 へ写す。軸ごとに基準の効き方(重み)を変える。地力は強く、連携・安定感は弱い
   - 補正: 同じ試合の同じロールの相手との差を、母集団(収集した全試合の参加者)の同じロールの分布で標準化し、試合ごとに新しさの重みを付けて平均する
   - 縮小: 補正は有効な試合数 n に応じて n / (n + k) 倍にする。試合が少ないほどランクの基準に近づく
   - ロールに依存する軸(レーン戦・集団戦・連携)は、大会のロールで遊んだ試合だけを使う
   - 期間は直近 120 日。新しさの重みは半減期 45 日。10 分未満の試合(リメイク)は除く
5. **根拠の軸は、出典つきの根拠からだけ作る。根拠は積極的に集める**
   - コール力: LTK と他の大会での役割、本人・チームメイトの発言、記事、視聴者の声(X・ブログ・note・まとめ・YouTube の説明やコメント・切り抜き)。肯定(コールする)と否定(コールを任せる)の両方を根拠にする。**コーチとしての指示も肯定の根拠に数える**(価値責任者「それだけちゃんと軸があるということ」2026-10-08)。他ゲームの IGL は弱い肯定とする(AI の起案)。価値責任者自身の確認(例: 龍巻ちせ・叶・空澄セナ・獅子堂あかりはコールしない側、2026-10-08)も、人が確認した根拠として数える。LTK に出場した 58 名は大会中に表出があるはずで、根拠が見つからないのは収集の不足として扱う(価値責任者の指示)。それでも根拠が無い選手は「データなし」とし、ランクや経験から推定しない
   - AI(Gemini・調査エージェント)が集めた根拠は出典の URL を必須とし、人が確認するまで「AI 収集(未確認)」と表示する
6. **事前値**(データの少ない軸の出発点): ランク帯、サモナーレベル、熟練度の合計、LoL 歴(調査で出典が得られた選手だけ)、LTK の過去戦績から作る。サモナーレベル・熟練度・LoL 歴は「遊んだ量」であり技量ではないため、ピックプールと大会経験の事前値だけに使う
7. **LTK の経験を、チームゲームの軸に効かせる**: 価値責任者の指示(2026-10-08)「LTK は密度の高い本格的なチームゲームとしての LoL に長期間真剣に取り組むもので、LTK の1シーズンの学びはソロキュー1年より圧倒的に上」。LTK の参加シーズン数と出場試合数を、集団戦・連携・安定感の点数に、ソロキューのデータとは別の項として加える(事前値だけでなく、データがある選手にも効かせる)。ソロキューのデータは5人の固定チームでの働きを測れないため、この項で補う。初期値は1シーズンあたり +0.4、上限 +1.2(AI の起案。価値責任者が確定する)。大会経験の軸でも、LTK の出場を他の大会より重く数える
8. **確度を全軸に付けて表示する**: 有効な試合数と新しさ、大会のロールの試合の割合、根拠の数と確認の有無から「高・中・低」を決める。事前値だけで決まった軸は「推定」と明示する
9. **常識の検査**: 価値責任者が確定した「明らかにこうである」という事実の一覧(初版 K-01〜K-07)を、評価の結果に対して機械で検査する。1 件でも反すれば公開を止める

## 検討した選択肢

| 案 | 性質(AI が整理) | 採らなかった理由 |
| --- | --- | --- |
| 固定の範囲で線形に換算する(F-002 の初版) | 単純で説明しやすい。範囲の決め方で偏りが出て、ロール差・ランク差を吸収できない(実データで確認) | (技術判断者の記入待ち) |
| 60 選手の中のロール内パーセンタイルだけで決める | 範囲を決めなくてよい。階級をまたぐと Master と Gold が同じ物差しで並び、絶対的な位置が分からない。母数が各ロール 12 名と少ない | (技術判断者の記入待ち) |
| 既存サイトの点数(OP Score・AI Score)を使う | 実装が少ない。式が非公開で根拠を示せない。自動取得は ADR-0002 で採らない | (技術判断者の記入待ち) |
| 機械学習で勝敗から重みを学ぶ | 重みを根拠で決められる。LTK の試合数が少なく、ソロキューの勝敗は大会と相関が弱いという報告がある | (技術判断者の記入待ち) |
| メカニクス・視界・オブジェクトを個人の軸にする(当初の起案) | データで測りやすい。視界・オブジェクトはチームの働きで、個人の評価になりにくい。メカニクスは直感的でない | 価値責任者の指示(2026-10-08)により採らない(AI が転記) |
| 調子を軸の1つにする | 一目で分かる。状態は全軸に効くもので、独立の能力ではない | 価値責任者の指示(2026-10-08)により、各軸に掛かる係数にした(AI が転記) |
| コール・マクロもランクや経験から推定する | 全員に数値が出る。「コールできないのに高い」を生む。既存のどのシステムも数値にしていない | (技術判断者の記入待ち) |

## 可逆性

| 項目 | 内容 |
| --- | --- |
| 後から変えられるか | 変えられる。軸の定義・重み・縮小の強さ・期間は設定ファイルに置く |
| 変えるとしたら必要なこと | 設定の変更と、常識の検査の再実行 |
| いつまでなら安く変えられるか | 勝率の推定(F-005)が軸の点数を入力に使い始める前 |

## 非機能への影響

| 項目 | 影響 |
| --- | --- |
| 性能 | 採点は収集の後の集計で一度だけ行う。60 選手 × 数十試合で数秒 |
| 可用性 | 影響なし |
| セキュリティ | 影響なし。生の応答は公開しない(ADR-0002) |
| 運用 | 常識の検査の一覧を人が育てる。根拠の軸の材料(過去戦績・定性の根拠)の入力が要る |

## 事業への影響

| 項目 | 内容 |
| --- | --- |
| 影響を受ける利用者・業務 | 作者本人。おかしな数字が1つでも見えると、予測全体を信じられなくなる |
| 顕在化が分かる兆候 | 常識の検査の失敗。画面を見て「この選手がこの軸でこの点はおかしい」と感じる箇所 |
| 回復に要する時間 | 設定の調整なら数時間、軸の定義の見直しなら 1〜2 日 |
| 取り消しの可否 | 人手で戻せる |
| 影響する必達基準 | 該当なし |

## 影響

- F-002 の「5軸」は、この決定の個人の 8 軸(設定で増減できる)に置き換わる。F-002 の基準1・2 と採点規則は F-009 に従って改める(F-002 の G-4 の再判定が要る)
- 収集(F-003)に、サモナーレベルと熟練度の取得、期間による試合の選び方を足す
- 大会経験とコール力は、調査の資料と視聴者の声を出典つきのスナップショットにする作業が要る(2026-10-08 に調査エージェントで全 60 名の収集を開始)
- 視界・オブジェクト・マクロはチームのページの指標になる(F-002 Task-3 のチームのページを拡張する)
- ソロキューの強さは大会の強さと同じではない。勝率の推定(F-005)では、軸の点数に加えて LTK の過去戦績とチームの構成を使う
