# ADR-0004: 選手の評価を「ランクの基準 + 同じ試合の対面との差」で作り、根拠の無い軸は数値にしない

## ステータス

提案(2026-10-08)。方針は価値責任者 takenori-kusaka の要求(2026-10-08「コールできないのにコール力が高い、マクロを分かっていないのにマクロが高い、が目に付いた瞬間すべての信頼を失う」「軸は 6〜8 に増やしてよい」「データが無い選手はランク帯・LoL 歴・サモナーレベルからおおよその中央値に」)による。採用は G-3 の判定記録で確定する。

## コンテキスト

F-002 の採点(5軸、固定の範囲で線形に換算)を 60 選手の実データにかけたところ、次の誤りが出た(2026-10-08)。

- SUP と JG の「レーン戦」が 10.0 に張り付く(CS の換算範囲がロールに合っていない)
- Master の ADC でも「チームファイト」が 3.8(キル関与率とダメージ割合の範囲がソロキューの実際の値より高い)
- 「プールとメタ適合」が使ったチャンピオンの数そのもの(得意を絞る選手ほど低い)
- 「コール・大会経験」が全員データなし

実データの分析(`docs/research/rating-methods.md` と同時期の作業。60 選手 × 約30試合、参加者のべ 16,490 人分)で、次が分かった。

- ソロキューで大会のロールを遊んでいない選手がいる(SHAKA の TOP は 29 試合中 2、Rainbrain の JG は 2、アステル・レダの JG は 3)
- 試合の新しさがばらつく(直近 60 日の試合が 0 件の選手が 7 名。前シーズンの試合も混ざる)
- 同じ試合の対面との差の指標(最大 CS 差、視界の差、対面比のダメージ)はランクとほぼ無相関(相関 0.10、−0.02、0.24)。ソロキューは同じ MMR 帯で組まれるため、対面との差は「自分のランクより強いか」を表す
- 既存の評価システム(Mobalytics GPI・OP.GG OP Score・DEEPLOL AI Score)と学術モデル(PandaSkill・SIDO)は、どれも「マクロ」「コール」を数値にしていない。学術モデルは、ロール別の評価、ロール内のパーセンタイル、試合数の少ない選手の平均への縮小、保守的な下限の表示を共通に使う

## 決定

1. **軸を 8 にする**(データの軸 6 + 根拠の軸 2)
   - データの軸: メカニクス / レーン戦 / 集団戦 / 視界 / オブジェクト / チャンピオンプール
   - 根拠の軸: 大会経験 / コール
2. **データの軸の点数 = ランクの基準 + 対面との差による補正(試合数で縮小)**
   - ランクの基準: 現在のソロランク(無ければ最高ランク、それも無ければ事前値)を 0〜10 へ写す。軸ごとに基準の効き方(重み)を変える。メカニクスは強く、視界・オブジェクトは弱い
   - 補正: 同じ試合の同じロールの相手との差を、母集団(収集した全試合の参加者)の中で標準化し、試合ごとに新しさの重みを付けて平均する
   - 縮小: 補正は有効な試合数 n に応じて n / (n + k) 倍にする。試合が少ないほどランクの基準に近づく
   - ロールに依存する軸(レーン戦・視界・集団戦の一部)は、大会のロールで遊んだ試合だけを使う
   - 期間は直近 120 日。新しさの重みは半減期 45 日。10 分未満の試合(リメイク)は除く
3. **根拠の軸は、出典つきの根拠からだけ作る**
   - 大会経験: LTK の過去の出場試合数と勝敗、プロの経歴(調査の出典つき)
   - コール: 出典つきの定性の根拠(報道・インタビュー・大会での役割)。**根拠が無い選手は「データなし」とし、ランクや経験から推定しない**
   - AI(Gemini)が下書きした根拠は「AI 推定(未確認)」と表示し、確度を「中」以下にする。人が確認したら外す
4. **オブジェクトの軸には上限を置く**: データ(ドラゴン・バロン・タワーへの関与)だけでは 7.0 を超えない。マクロの理解を示す定性の根拠があるときだけ上限を外す
5. **事前値**(データの少ない選手の出発点): ランク帯、サモナーレベル、熟練度の合計、LoL 歴(調査の出典つき)、LTK の過去戦績から作る。サモナーレベルと熟練度は「遊んだ量」であり技量ではないため、チャンピオンプールと経験の事前値だけに使う
6. **確度を全軸に付けて表示する**: 有効な試合数と新しさ、大会のロールの試合の割合、根拠の数から「高・中・低」を決める。事前値だけで決まった軸は「推定」と明示する
7. **常識の検査**: 価値責任者が確定した「明らかにこうである」という事実の一覧(例: Challenger の選手のメカニクスは Gold の選手より高い、ロール外の試合しか無い選手のレーン戦の確度は低)を、評価の結果に対して機械で検査する。1 件でも反すれば公開を止める

## 検討した選択肢

| 案 | 性質(AI が整理) | 採らなかった理由 |
| --- | --- | --- |
| 固定の範囲で線形に換算する(F-002 の初版) | 単純で説明しやすい。範囲の決め方で偏りが出て、ロール差・ランク差を吸収できない(実データで確認) | (技術判断者の記入待ち) |
| 60 選手の中のロール内パーセンタイルだけで決める | 範囲を決めなくてよい。階級をまたぐと Master と Gold が同じ物差しで並び、絶対的な位置が分からない。母数が各ロール 12 名と少ない | (技術判断者の記入待ち) |
| 既存サイトの点数(OP Score・AI Score)を使う | 実装が少ない。式が非公開で根拠を示せない。自動取得は ADR-0002 で採らない | (技術判断者の記入待ち) |
| 機械学習で勝敗から重みを学ぶ | 重みを根拠で決められる。LTK の試合数が少なく、ソロキューの勝敗は大会と相関が弱いという報告がある | (技術判断者の記入待ち) |
| コール・マクロもランクや経験から推定する | 全員に数値が出る。「コールできないのに高い」を生む。既存のどのシステムも数値にしていない | (技術判断者の記入待ち) |

## 可逆性

| 項目 | 内容 |
| --- | --- |
| 後から変えられるか | 変えられる。軸の定義・重み・縮小の強さ・期間は設定ファイルに置く |
| 変えるとしたら必要なこと | 設定の変更と、常識の検査の再実行 |
| いつまでなら安く変えられるか | 勝率の推定(F-005)が軸の点数を入力に使い始める前 |

## 非機能への影響

| 項目 | 影響 |
| --- | --- |
| 性能 | 採点は収集の後の集計で一度だけ行う。60 選手 × 数十試合で数秒 |
| 可用性 | 影響なし |
| セキュリティ | 影響なし。生の応答は公開しない(ADR-0002) |
| 運用 | 常識の検査の一覧を人が育てる。根拠の軸の材料(過去戦績・定性の根拠)の入力が要る |

## 事業への影響

| 項目 | 内容 |
| --- | --- |
| 影響を受ける利用者・業務 | 作者本人。おかしな数字が1つでも見えると、予測全体を信じられなくなる |
| 顕在化が分かる兆候 | 常識の検査の失敗。画面を見て「この選手がこの軸でこの点はおかしい」と感じる箇所 |
| 回復に要する時間 | 設定の調整なら数時間、軸の定義の見直しなら 1〜2 日 |
| 取り消しの可否 | 人手で戻せる |
| 影響する必達基準 | 該当なし |

## 影響

- F-002 の「5軸」は、この決定の 8 軸(設定で増減できる)に置き換わる。F-002 の基準1・2 と採点規則は F-009 に従って改める(F-002 の G-4 の再判定が要る)
- 収集(F-003)に、サモナーレベルと熟練度の取得、期間による試合の選び方を足す
- 大会経験とコールは、調査の資料を出典つきのスナップショットにする作業が要る
- ソロキューの強さは大会の強さと同じではない。勝率の推定(F-005)では、軸の点数に加えて LTK の過去戦績とチームの構成を使う
