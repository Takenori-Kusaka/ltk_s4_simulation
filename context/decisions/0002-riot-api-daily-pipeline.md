# ADR-0002: Riot 公式 API と self-hosted runner の日次パイプラインでデータを更新する

## ステータス

提案(2026-10-08)。技術判断者 takenori-kusaka が会話で「Riot 公式 API」「GitHub Actions の self-hosted runner で1日1回の再収集と再シミュレーション」「この PC の Gemini CLI による簡単な AI 分析」を選択済み。採用は G-3 の判定記録で確定する。

## コンテキスト

選手ごとのランク・得意ピック・チャンピオン別勝率・メタ適合性を数値で見たい(価値責任者、2026-10-08)。op.gg などのサイトは利用規約で自動取得を禁じている可能性が高く、公開リポジトリで取得結果を再配布する点にも注意が要る。大会期間(10/15〜11/22)は1日1回の更新で足りる。作者の PC には Gemini CLI(0.62.0)が入っており、`gemini -p` の非対話の実行で応答が返ることを 2026-10-08 に確かめた。

## 決定

1. **数値は Riot 公式 API から取る**
   - アカウント: account-v1(by-riot-id。地域ルーティング asia)で Riot ID から PUUID を引く
   - ランク: league-v4(プラットフォーム jp1)
   - 試合履歴: match-v5(地域ルーティング asia)。直近の試合を差分で取り、選手×チャンピオンの勝率・使用数を自前で集計する
   - 熟練度: champion-mastery-v4(jp1)
   - メタ適合性: 公開のパッチノートと、集計した試合データから算出する方式を、機能仕様で定める
2. **API キーはリポジトリに置かない**。self-hosted runner の環境変数か GitHub Actions のシークレットに置き、SPA のバンドルには含めない
3. **GitHub Actions の self-hosted runner(作者の PC)で1日1回、収集 → AI 分析 → シミュレーション → ビルド → GitHub Pages へ配置**を行う。手動実行(workflow_dispatch)も用意する
4. **AI 分析は Gemini CLI を非対話(`gemini -p`)で呼び、テキストの生成だけに使う**。結果は「AI の分析」と明示して画面へ出し、数値の正本にしない
5. 実際の試合結果・ニュース・考察は手入力の JSON で持ち、API の数値と合わせて使う

## 検討した選択肢

| 案 | 性質(AI が整理) | 採らなかった理由 |
| --- | --- | --- |
| op.gg などの画面の自動取得 | 集計済みの数値がすぐ得られる。利用規約に反する可能性が高く、画面の変更で壊れる | (技術判断者の記入待ち) |
| 手入力の JSON/CSV だけ | 最も単純で規約の心配がない。60選手の数値を毎日更新する手間が大きい | (技術判断者の記入待ち) |
| GitHub ホストのランナー | PC を起動しておく必要がない。API キーをシークレットに置く。Gemini CLI の認証を持ち込みにくい | (技術判断者の記入待ち) |

## 可逆性

| 項目 | 内容 |
| --- | --- |
| 後から変えられるか | 変えられる。取得層を差し替えても、集計後のデータ形式を保てば SPA は変わらない |
| 変えるとしたら必要なこと | 取得スクリプトの差し替え。集計後のデータ形式(機能仕様で定める)を保つ |
| いつまでなら安く変えられるか | 集計後のデータ形式を SPA が読み始める前 |

## 非機能への影響

| 項目 | 影響 |
| --- | --- |
| 性能 | 開発キーの上限は 20 回/秒・100 回/2分。60選手×直近の試合の初回取得は1時間程度かかる見込み。以降は差分の取得 |
| 可用性 | PC が起動していない日は更新されない。前日のデータが表示され続ける |
| セキュリティ | **公開リポジトリの self-hosted runner は、フォークからの PR のワークフローが作者の PC で動く危険がある**。日次のワークフローは schedule と workflow_dispatch だけを契機にし、pull_request では self-hosted runner を使わない。リポジトリの設定で、外部の協力者からの PR のワークフローの実行に承認を必須にする。Gemini CLI は `--yolo`(ツールの自動承認)を付けずに呼ぶ。収集した外部の文章を入力にするため、ツールの自動実行を許すとプロンプトインジェクションで PC 上の操作が行われ得る |
| 運用 | 開発キーは24時間で失効する。日次で回すには個人用 API キー(Personal API Key)を Riot Developer Portal で申請する。Riot のポリシーにより、公開する製品は登録が要る |

## 事業への影響

| 項目 | 内容 |
| --- | --- |
| 影響を受ける利用者・業務 | 作者本人。更新が止まると古い予測を見ることになる |
| 顕在化が分かる兆候 | 日次のワークフローの失敗、API の 401/403(キー失効)、429(上限超過)、画面の「最終更新日時」が前日より古い |
| 回復に要する時間 | キーの再発行なら数分。個人キーの承認待ちは数日〜数週間(Riot の審査による) |
| 取り消しの可否 | 人手で戻せる |
| 影響する必達基準 | 該当なし |

## 影響

- 各選手の Riot ID(ゲーム名#タグ)の一覧が入力として必要になる。調査で op.gg の URL から分かったものと、未確定のものがある
- Riot の利用規約とポリシー(Developer API Policy)に従う。取得した試合データを第三者へ再配布する範囲は、集計後の数値に留める
- この決定は、予測モデルの方式(Elo・ベイズ更新等)を決めない。機能仕様と別の ADR で扱う
